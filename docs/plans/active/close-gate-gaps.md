## Context

The `historical-code-review` sweep (`docs/self-improvement/historical-review-findings.md`, ~440 merged PRs #602–#1028) surfaced recurring defect **classes**, not just instances. Per `AGENTS.md` § "gate, don't trust", every fixed class should earn a code-enforced gate so new code can't reintroduce it. A session audit (2026-06-08) verified the gates are **partial**:

- **Live + working** (hit this session): `smatchet_patch_or_die` (`cmake/SmatchetThirdParty.cmake`), `no-glfw-in-core-headers` lint, ImWchar `static_assert` (`SmatchetImGuiFonts.cpp:25`), comment-noise gate, Test-delta gate.
- **Live but with a verified blind spot**: the **Pillar-2 sync-I/O scanner** (`scripts/dev/pillar2-scan.sh`) regex matches only *direct* primitives (`cpr::Get/Post`, `std::ifstream`, `popen(`, `system(`, `SQLite::…`, `.lock()`) — it does **not** see the project's own blocking **wrapper** functions, which is precisely why the entire surviving sync-I/O cluster (#565 `ConfigManager::SaveAnnotateAnalysis`, #611 `LoadPersistentViewsFromDisk`, #732 `ConfigManager::Save`, #761 `P4RunCommand`) slipped through.
- **No gate at all**: semantic doc-signature drift (the `UpdateField(…, outError)` leaf-doc slip this session), `Result`/`Optional` exception-safety (#1017), the gate-false-pass meta-class (#918/#663/#784/#978), fresh-clone configure correctness (the cpr-submodule failure, #1031), and the `tests` glob-vs-list assert (#5, unconfirmed).

**Self-demonstration (2026-06-08):** authoring *this very plan* tripped two more gate-gaps, now folded in as Gap **H** — (1) the local `scripts/dev/test-docs.sh` mirror passed **10/0** on the brand-new uncommitted plan file, yet CI's `test-plan-ref-integrity` + markdown-link checks failed on the same content once committed (the mirror's changed-file checks scan only git-diffed files, so a new *untracked* file false-passes pre-push); and (2) the plan-template § Archive `git mv` step, when its `<slug>` placeholder is expanded to the literal filename, manufactures a dangling `docs/plans/shipped/<name>.md` reference that `test-plan-ref-integrity` flags. Both are textbook instances of the thesis — gates that gave false-green — and are exactly why the local mirror must match CI scope.

**Intended outcome:** after this lands, every recurring class from the sweep either **fails a PR gate** when reintroduced, or carries a documented, tractable reason it can't be gated. The mop (fixing instances) follows the leak-fix (the gate).

## Approach

Close each gap **gate-first**, one gap per PR: extend/repair the existing gate (or add a new one), then fix-or-grandfather the existing violators *under* the now-active gate so it goes green. Ordering puts the highest-leverage gate (the Pillar-2 wrapper blind spot — it alone covers 4+ live findings) first, the cheap/contained gates next, the one instance no static gate fits (#1017, Slice 6 — *fixed*, with a doctest as the regression guard) after, and the doc-validation mirror/template hardening (Gap H, Slice 8) last.

The non-obvious gate-design call, settled in the grill (2026-06-08): for the **wrapper** class the static scanner is the *wrong* tool. A file-level grep cannot distinguish a `ConfigManager::Save` inside a `LaunchBackgroundTask` lambda (legit) from one on the render path (the bug) — and the code proves the cost: **55** legit `ConfigManager::Save*` sites already sit in `Source/Core/src/Ui/` against only **9** total `PILLAR2_WORKER_ONLY` annotations, so a wrapper-aware regex would demand a 55-site annotation sweep, bury the real violators in a grandfather baseline, and rubber-stamp the annotation into noise. The precise gate for a function that is *legitimately called both on and off thread* is a **runtime UI-thread-affinity assert inside the wrapper itself** — zero false positives (an off-thread call never trips it), zero annotation burden, caught by the existing bucket-E/sanitizer harness where the bug actually manifests (the call *executing* on the UI thread). The static scanner is left untouched for *direct* primitives, where "on a render path = suspect" holds. (See § Risks for why this is ADR-worthy.)

## Slices (ordered — implement one PR each)

**Slice 1a — UI-thread-affinity assert in the blocking wrappers (the gate).** Add a **runtime** thread-affinity guard at the top of each blocking wrapper (`ConfigManager::Save*`, `ConfigManager::Load[A-Za-z]*FromDisk`, the p4 subprocess wrapper behind `P4RunCommand` — grep-confirm the full blocking set first): debug/sanitizer build → `SMATCHET_ASSERT(!UiThreadAffinity::IsOnUiThread())`; ship build → soft-degrade (`LOG_ERROR` once + a `perf_temp`-style marker, **no crash** — Pillar-3 graceful degradation). **Layering wrinkle (pre-flight-confirmed):** the publish-once UI-thread-id check already exists but is **private to `AppController`** (`AppController::IsOnUiThread()`; `uiThreadId_` set once in `Initialize` — symbol-only ref, the line drifts) — and the wrappers sit *below* `AppController` (in `Config/` / p4), so lift the id into a tiny standalone low-layer utility (`Source/Core/include/UiThreadAffinity.h`: `SetUiThread()` called once at UI init + `IsOnUiThread()`) that both layers query without a layering inversion. The static `pillar2-scan.sh` is **unchanged** (it stays correct for direct primitives). **~4 files** (the affinity util + its set-at-init wiring + the 3 wrapper sites). **No false positives, no annotation sweep.**

**Slice 1a-rollout note:** the assert is **debug/sanitizer-only** as a hard failure; it surfaces a violator only when that code path actually executes on the UI thread under a test/bucket-E/sanitizer run — so it is a *runtime* gate, not a compile/PR-static one. That's the correct trade for this class (a static gate provably can't see lexical scope); the existing bucket-E + ASan/UBSan CI lanes are where it bites. If a violator path has no bucket-E coverage, Slice 1b adds it.

**Slice 1b — fix the violators the assert now catches (+ the test that drives each path).** For each violator: first ensure a bucket-E/scenario test **drives its exact render-path** (so the Slice-1a assert *fires* pre-fix — proving the gate works, not just exists), then fix it off-thread so the assert passes: #565 `AnnotateAnalysisUi_Preferences.cpp:212` → `PersistAnnotateCfg("edit_color")` (same-file off-thread helper); #732 `SmatchetPreferencesUi_Templates.cpp` → `MarkPrefsDirty(d)` (sibling sub-tabs already do this); #611 `SmatchetToolbarUi.cpp:124` → `LaunchBackgroundTask` + `PostToMainThread` + cue. **#761 needs a re-grep first** — `P4RunCommand` has **0** call-sites in `Source/Core/src/Ui/`, so the cited `AnnotateAnalysisUi_Window.cpp:191` reaches p4 through a different wrapper; confirm the actual blocking call before fixing. **Split per-file**; route to `spike-hunter`/`grid-engine`/`p4-annotate`. *(If any fix needs product judgement, file the GitHub Issue per ADR-0014 instead.)* The "drive-the-path test first" step is what converts the debug-only runtime assert from theoretical into an actually-firing CI gate per violator.

**Slice 2 — interface-header-vs-leaf-doc WARN heuristic (Gap B; grill Q2 reframe — NO signature parsing).** The rejected design was a delta-lint that parses `` `Type::method(param-list)` `` out of *markdown prose* and diffs param names against the header — fragile (C++ signatures from English), and the class fired exactly **once** all session (a doc-only, non-bug). Instead ship the cheap heuristic: a delta rule (`agents/scripts/project/test-lint-rules.sh`) keyed off a small curated **interface-header → leaf-doc** map (e.g. `Source/Core/include/ITracker*.h` + `Source/Core/include/Tracker/*Client.h` → `Source/Core/src/Tracker/{CONTEXT,AGENTS}.md`) that **WARNs** when a PR's diff touches a mapped interface header but **not** its leaf doc — "you changed a documented contract; confirm the leaf doc still matches" (exactly the `ITrackerIssueMutations.h`-changed-without-`Tracker/AGENTS.md`-touched shape of this session's slip). No prose parsing, no false-positive-prone signature differ. **Spike for noise first; ship WARN-only; promote past WARN only if it proves quiet** (mirror the `duplication` calibration). `--selftest`: a mapped-header change with no leaf-doc touch **WARNs**, with the touch **passes**. **~3 files** (the rule + its header→doc map + the contract-card row in `AGENTS.md`). *(If even the WARN proves noisy, fall back to Gap F's posture: accept the class ungated — the subsystem-guide rule + historical-review sweep already cover a once-a-session doc slip.)*

**Slice 3 — every gate `--selftest` must assert a failure case (Gap C; grill Q4 reframe).** The rejected design was a meta-gate that "feeds every gate a known-bad fixture and asserts non-zero" — **not buildable**: each gate's failing input is semantic (a malformed coverage file ≠ a ledger-missing-PR ≠ a dangling ref), so no universal bad input exists to synthesize. The feasible, durable version is two parts: **(3.1) one-time audit + backfill** — walk every gate script under `agents/scripts/{core,project}/` exposing `--selftest`, and where the selftest only exercises the *pass* path, hand-write a **negative fixture** proving it FAILS on bad input (the substance; the class behind #918/#663/#784/#978 was gates whose selftest only ever passed). **(3.2) a shape convention-check** (`agents/scripts/core/test-gate-selftests.sh` + a `tests/bats` case) that the meta-runner *can* enforce: every `--selftest` body must contain **both** a pass-expectation and an explicit fail-expectation marker (a grep-able `# selftest: asserts-failure` convention), so a *future* gate physically can't ship a pass-only selftest. It checks the **shape**, not the semantics. **~3–5 files** (the convention-check + bats + the backfilled negative fixtures across audited gates).

**Slice 4 — scheduled fresh-clone configure CI (Gap D; grill Q3 — nightly/weekly, NOT per-PR).** A **`schedule:`-triggered** workflow (nightly or weekly) that configures into a **clean temp `FETCHCONTENT_BASE_DIR`** (forces a real fresh `git clone` of every git dep) and asserts `Configuring done`. Decision (grill Q3): the failure class can only trigger on the rare PR that **adds/changes a git `FetchContent_Declare`** (after #1031 fixed all 10 current declares), so paying a multi-minute fresh-clone on *every* PR is bad cost/value — a rare regression caught within 24h is fine, with develop's post-merge CI as the backstop. (No path-triggered PR variant either — the user's call is scheduled-only; a `paths: [CMakeLists.txt, cmake/**]` PR trigger was considered and dropped for simplicity.) Route to `build-doctor`. **~1–2 files** (`.github/workflows/*.yml` + maybe a `scripts/dev/` helper).

**Slice 5 — glob-vs-list test assert (Gap E).** Confirm whether a configure-time assert that every `tests/Core/*.test.cpp` appears in the explicit `add_executable` list already exists (the 2026-06-08 audit could not find one); if absent, add it to `tests/CMakeLists.txt` (a globbed set diffed against the hand-list → `FATAL_ERROR` on a missing entry) so a new test file can't be silently uncompiled (false-green). Route to `test-rig`. **~1 file.**

**Slice 6 — #1017 `Result<T,E>` copy-assignment exception-safety (grill Q5 — REACHABLE, not latent).** Pinned by code: `Result::operator=(const Result&)` (`SmatchetResult.h:142`) does `Destroy()` **then** placement-news a `T(copy)` — and that copy **can throw `bad_alloc`** for `Result<vector/string/json>` (the tracker layer's heaviest `Result` types), leaving storage destroyed but `ok_==true` → the next `~Result()` double-destroys = **UB** (the move-assignment path at `:157` is safe — noexcept moves). Fix: **construct-then-commit** — build the new `T`/`E` in a local **first**, then `Destroy()` + commit it into storage via a **noexcept move** only after the throwing copy succeeded (mirror the already-correct `Optional<T>` in the same header). Also fix the misleading `// no heap allocation` comments on the copy lines (a `vector`/`string`/`json` copy *does* allocate). A `test-rig` doctest with a throwing-**copy** payload type, exercised through **copy-assignment**, is the regression guard. **Why not a gate:** `static_assert(is_nothrow_move_constructible<T>)` only closes the (already-safe) move path; `static_assert(is_nothrow_copy_constructible<T>)` would **ban `Result<vector<CachedTicket>>`** (the type we use) — so no static gate fits; the fix + doctest is the answer. **~2 files.**

**Slice 7 — process/doc encodings + residue (Gap G).** Add the serial-migration **worktree-reuse** one-liner to `docs/agent-rules/process-rules.md` (already filed as a `process.md` self-improvement entry this session); prune the now-superseded "configure via PowerShell to dodge the cpr submodule step" guidance from `build.md` / the 2026-06-07 infra entry (Gap D's CI job is the real gate). **~2–3 doc files.**

**Slice 8 — doc-validation: local mirror matches CI + template self-ref hardening (Gap H).** Two sub-fixes for the false-passes observed authoring this plan: **(8a)** make `scripts/dev/test-docs.sh`'s changed-file checks (`test-markdown-links`, and the ref/anchor scans) also include **untracked** files (`git status --porcelain` / `git ls-files --others --exclude-standard`, not just the diff against `origin/develop`), so a brand-new uncommitted plan/doc file gets the same scope CI gives it — pre-push green then means CI-green. Ship a `--selftest` proving an untracked file with a dangling link **FAILS** locally. **(8b)** Harden the plan-template Archive footgun: add an explicit authoring note in `docs/plans/active/_plan-template.md` that step 2 keeps the literal `<slug>` placeholder (never expand to the real filename — it manufactures a dangling `shipped/` ref), **and/or** teach `agents/scripts/core/test-plan-ref-integrity.sh` to skip a `docs/plans/shipped/<basename>.md` reference that occurs inside a plan's own § Archive block (self-reference, not a real cross-link). Route to `mechanic`/`build-doctor`. **~3 files.**

## Risks / non-goals

- **Risk — the Slice-1a runtime assert is debug/sanitizer-only, so it only fires on a path that a test actually exercises on the UI thread** (weaker than a compile/PR-static gate). Accepted with mitigation: a static gate *provably cannot* see lexical scope for a both-on-and-off-thread wrapper (the 55-site swamp), so runtime is the right tool; Slice 1b's mandatory "drive-the-path test first" step converts it from theoretical to actually-firing per violator, and the existing bucket-E + ASan/UBSan lanes run it in CI. The static scanner still covers direct primitives.
- **Risk — `UiThreadAffinity` set-once timing.** Mitigation: mirror `AppController`'s publish-once discipline (`uiThreadId_` set in `Initialize` before any worker spawns, then never mutated — see the comment on `AppController::IsOnUiThread()`); a wrapper called before `SetUiThread()` runs sees "unknown thread" → must **not** assert (fail-open during startup), only assert once the UI thread is registered.
- **ADR candidate (offered separately):** "runtime thread-affinity assert for wrapper-shaped sync-I/O, static scanner for direct primitives" is hard-to-reverse (it sets the *kind* of gate the project uses for this class), surprising without context (a reader expects the scanner to be extended), and the result of a real trade-off (static-swamp vs runtime-coverage-dependence) — record it as an ADR when Slice 1a lands.
- **Risk — Slice 2's header-vs-leaf-doc heuristic nags** on interface-header edits that don't actually change anything the leaf doc pins (e.g. a comment or a non-documented method). Mitigation: WARN-only (never blocks), curated header→doc map (only the genuinely-documented interfaces), spike for noise before shipping, and the explicit fallback to accept-ungated if even the WARN is noisy. No false-positive *failure* is possible because it never hard-fails.
- **Risk — Slice 6 destabilises the foundational `Result<T,E>`.** Mitigation: mirror the *already-shipped* `Optional<T>` pattern in the same header exactly; the doctest with a throwing-**copy** type exercised through **copy-assignment** is the proof; dual-target build + full `SmatchetTests` is the blast-radius check (the tracker layer is now its biggest consumer).
- **Non-goal — the user-visible *correctness* instances that aren't sync-I/O**: #854 (offline scalar-edit data-loss), #975 (components-marker leak), #671 (orphaned subprocess), #948 (migration key). These are **not gateable by the Pillar-2 scanner** and need product judgement → **GitHub Issues per ADR-0014**, tracked separately, not in this plan.
- **Non-goal — sweeping the unswept PRs (#541 → #13)**: that's the historical-review backlog's own resume path, not this plan.
- **Non-goal — a general C++ signature/AST doc-checker**: Slice 2 is the cheap header-touched-without-leaf-doc WARN heuristic (grill Q2), not a clang-based signature verifier (cost ≫ value).
