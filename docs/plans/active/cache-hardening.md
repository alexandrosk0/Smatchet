## Context

The user asked for a review of how Smatchet uses its caches and whether the cache can be retained between restarts. Answer: **often it is not, and the root cause is the CWD-relative `DbPath`.** `kDefaultDbPath` is the bare name `"Smatchet_LocalCache.sqlite"` (`Source/Core/include/SmatchetDefaults.h:14`), seeded into `cfg.DbPath` at `ConfigManager_Load.cpp:1093` and opened unresolved at `AppController_Init.cpp:271/275` (`std::make_shared<LocalCacheManager>(dbPath)`). The file therefore lands wherever the process was launched from; a launch from another directory (shortcut, Finder, terminal, IDE) silently starts an empty cache, strands queued offline writes in the old file, and contradicts `Config/ConfigManager.h:867-872`, which says the cache lives in the storage-mode dir. Unreal (absolute `Saved/` path, `SmatchetImGuiPluginModule.cpp:104`) and Android (`android_main.cpp:396-398` prefixes `dataDir`) are already absolute.

The same review turned up adjacent defects, verified against the code, that this plan fixes together because they share the cache layer:

- **Data loss** — the one shared `SQLite::Database db` (`LocalCacheManager.h:292`, `OPEN_FULLMUTEX` at `LocalCacheManager.cpp:259`) is held under `stmtMutex_` only by `RunWriteTxnWithBusyRetry` (`:226-254`) and `CommitLeftViewDepartures`; ten other transactions run unlocked, so one thread's rollback can undo another's queued write (H1). A cache-open throw aborts standalone boot and crosses Unreal's C ABI (R2). Corruption quarantine (`:298-316`) rebuilds empty with no salvage and no notice (R3). Saves racing shutdown are stranded (K2).
- **Staleness / poisoning** — per-type editmeta from one uneditable issue narrows the whole type (E1); live transition and component lists never expire and a live transitions list is served for any from-status (S1/S2).
- **Unbounded growth / leaks** — evicted ImGui user textures are never destroyed (T1), DX12 SRV heaps alias (T2), whole `backend_key` namespaces are never dropped (M3), `luaFieldCache_` and the live transitions map grow without bound (I4/S5).

After this lands: the default cache lives at one absolute path under the user-data dir and survives restarts from any CWD (legacy CWD files are imported read-only); no cache write is lost to an unserialized connection, a failed open, corruption, or shutdown; every lookup cache is bounded and never serves another state's answer as live.

**Findings dropped after verification** (kept out of the work; listed so nobody re-raises them):

- M3 (part): `lookup_cache` growth inside a configured namespace is bounded by key count, not issue count — no trim. `*_dead` rows are queue tables (never swept). `left_view_history` rows carry their own `issue_key`/summary (`LocalCacheManager_LeftViewHistory.cpp:98`) and stay valid after a purge.
- M4 (part): `TicketSyncService.cpp:377` is the test-only `ApplyIssueFetchPack` seam (`TicketSyncService.h:104-111`), not a hot path; fixed opportunistically in RP-1 only.
- K2 (part): "saves still queued after the 5 s flush are dropped" — wrong; a running drain continues and `JoinBackgroundTasks` (`AppController.cpp:310`) joins it. Only posts racing `shuttingDown_` are lost.
- L3 (part): the in-process recreate double-send — refuted (`AppController_LocalCacheDb.cpp:289-299`: `use_count()==1`, `reset()`, failed weak lock; replay passes serialize on `replayInFlight_`). Only the cross-process case is real.
- E4 (part): "roster restored only when the catalog snapshot is fresh" — refuted (`Ui/SmatchetUI.cpp:1793` calls it on every catalog fetch). A bool-returning `LaunchBackgroundTask` was rejected (≈161 call sites, misses `AppController.cpp:377`).
- S1 (part): "sync never invalidates transitions" — refuted (`TicketSyncService.cpp:649-652` → `RemoteChangeInvalidationPure.h:17-24`).
- S3 (as proposed): gating learned-workflow rows on `LookupCacheTtlSec` would drop every row (default 0) — reduced to an optional own limit (LS-7).
- A2, A6 (part): directory rebinding has no production trigger (fixed cheaply anyway); another site's attachments are never served (allowlist precedes the cache, `AttachmentAppUpdateService.cpp:326-330`) — only same-site cross-account is fixed.
- P1: `P4ClPreview` keyed by changelist — the app never switches P4 server at runtime (`P4Annotate.cpp:57-58`). No action.
- I4 (part): `luaFieldCache_` key not backend-scoped — harmless (the hit needs every input to match, `AppController_LuaBindings_Draw.cpp:589-591`).
- R3 (part): WAL re-pairing in salvage is not the main route — `LocalCacheManager.cpp:305` closes the connection (checkpointing the WAL) before quarantine; best-effort only.
- T1 (mechanism): the review's `UnusedFrames` explanation was wrong; the real bug is worse (user textures never reach `Destroyed`, see FI-1).

## Approach

**Order by risk.** Data-loss fixes first (db-path, sqlite-concurrency), then shutdown loss and texture leaks, then staleness and growth. Each PR is safe on its own; dependencies are explicit in § Implementation handoff.

**db-path (DB).** `AppController::InitConfig` — the chokepoint all three hosts call — freezes `localCacheDbPath_` as an absolute path through a pure planner (`LocalCacheDbPathPure.h`): absolute passes through; relative/empty resolves against `ConfigManager::GetUserDataDirectory()` (CWD captured once as a last resort). The planner also lists legacy locations (CWD, runtime-asset dir, shared user-data dir). On first launch a worker imports the best-ranked legacy file **read-only** (rank: live pending rows, then ticket rows, then mtime) via SQLite Backup (`rc == SQLITE_DONE` + `quick_check == ok`) under a `<target>.init-lock`, publishing with a no-replace rename; legacy files are never written. The open itself moves onto `cacheRecreateWorker_` behind the existing `cacheRecreating_` gate, so the UI thread does no startup SQLite; a non-corrupt failure publishes a session-only `:memory:` cache (`Unavailable`) so reads and sync work while durable enqueues are refused with an honest reason (`CacheEnqueueBlock`). Corruption salvages `pending_*` + `cache_meta` from the quarantined file and persists a recovery record shown in Preferences. Trade-off: reusing the one recreate gate gives hold/replay and recreate exclusion for free; the cost is a small enum so each gate consumer can ask *why* the gate is up.

**sqlite-concurrency (SQ).** One non-recursive connection mutex held for the whole of every public `LocalCacheManager` method, compiler-enforced: `db` becomes private `db_`, reachable only via `conn(const ConnGuard&)`. Every multi-statement write goes through one member template `RunTxn_` (today's `RunWriteTxnWithBusyRetry` made a member that returns the body's value). Same-thread re-entry throws `std::logic_error`. Before the lock lands, per-frame UI-thread callers (AI chat hydrate, main-state Lua `get_ticket`) move off the connection (SQ-0), because a whole worker operation now blocks every other caller. On top: `RETURNING` ids stepped to `SQLITE_DONE` (a failed autocommit COMMIT throws), `exec()` change counts, deferred read snapshots for ticket reads, and an owner-token `sending` claim so a second process never double-sends. Rejected: a DB worker thread (≈40 synchronous call sites become futures for the same serialization) and a connection per thread (breaks `CloseSignal` and `:memory:` fixtures).

**sqlite-retention-perf (RP).** Chunked `GetTicketsByIds` (150 ids/chunk); after a single-ticket save, apply the saved row in memory instead of re-reading the namespace, with a generation/backend-key-tagged saved-row overlay so an older wholesale refresh cannot overwrite it; a bounded tail `Flush` after `JoinBackgroundTasks`; pane-owned id sets persisted as lookup kind `pane_owned_ids` so panes keep their scope across restarts; an age-based (90 d) once-per-24 h namespace sweep of cache tables only; `auto_vacuum=INCREMENTAL` on new files. The overlay beat a single-row re-read because that alone cannot stop an older wholesale read from overwriting the row, and losing that race would discard the fresher sibling rows it carries.

**editmeta (EM).** Per-type edit permissions move to `[backendKey][project][type]` scope entries that are promoted only from a *representative* (≥ 1 editable field) fetch; a new `ITrackerFieldCatalog::IssueEditMetaVariesPerIssue` capability limits per-row fetches to Jira and GitHub commit rows. Fetches carry generation tickets; scope saves and the user roster go to `SerialTaskQueue`s (latest-wins for the roster). A single-owner `LaunchClaim` releases every launch latch exactly once whether the task ran, was dropped, or the launch threw.

**lookup-staleness (LS).** `KeyedLookupCache` gains an opt-in admission rule (`FetchAdmission{LiveMaxAge, Revalidate}` + a stale predicate) that keeps the default behaviour byte-for-byte. Transitions are served live only for the from-status they were fetched for; components revalidate on Refresh and in the post-sync warm past `lookup_live_max_age_sec`; learned edges get tombstones; the live transitions map is pruned to active tickets over a cap; an over-cap project list is never saved. Fresh keeps its meaning, "fetched live this session" — giving `ClassifyFreshness` an age would have changed every cue (a UI change).

**file-image-caches (FI).** One frame-safe texture-destroy state machine in `SmatchetImageTextureCache` ticked from the single unconditional per-frame site, plus `DropAllForContextTeardown` before every `ImGui::DestroyContext`; DX12 SRV heaps to 1024; one binary atomic-write primitive in layer-0 `FileIo` that `ConfigManager::AtomicWriteTextFile` delegates to; attachment-cache temp/orphan cleanup; a worker-only icon disk cache (SHA-256 names, capped fetch, decode off the UI thread, exactly one non-droppable completion); 7-day icon revalidation and a size-capped prune; attachment entries namespaced by Jira site key; uncached attachments under `<userData>cache/attachment_tmp/`; a hysteresis sweep for `luaFieldCache_`. Key changes are migration-free (a one-time re-download) so no user file is renamed and downgrade stays safe.

## UX Pillar callouts

- **Pillar 1 (perf, 144 Hz / 6.94 ms)**: no steady-state regression. Per frame: one atomic load + empty-string check until the startup notice/banner is consumed (DB); one uncontended mutex + two relaxed atomics per cache call (SQ); one atomic time compare in `TickAllContexts` (RP-5); a prefix substring + 3 hash lookups per editable cell (EM — replaces an own-entry hit); one string compare + one limits copy per `Ensure` while a status combo is open (LS). Wins: a cell edit's post-save work drops from 3 full-namespace scans to an O(rows) replace (RP-2); the icon path loses all UI-thread filesystem calls and stb decode (FI-5); `luaFieldCache_` sweep is amortized O(1) (FI-8).
- **Pillar 2 (UI never blocks > 100 ms without a cue)**: every startup SQLite step (import, ctor + busy retries, migrations, legacy sweeps, salvage) moves to `cacheRecreateWorker_`, with an "Opening the local cache…" cue after 250 ms (DB-C); per-frame cache readers leave the UI thread (SQ-0); scope saves and roster saves leave the calling thread, removing an inline SQLite write on the palette path (EM-2); icon reads/decodes/writes, prune, revalidation, purges, attachment cleanup and temp sweep are worker-only and marked `PILLAR2_WORKER_ONLY`. **Named exception**: click-driven `QueueCreateOffline` (`Ui/SmatchetNewIssueDraftUi.cpp:351`, `Ui/SmatchetQuickCreateIssueUi.cpp:356`, Lua `create_issue`) does one synchronous INSERT that can now wait behind a whole worker operation; measured by the SQ-2 bench and the ConnGuard UI-wait tripwire, made async in a follow-up (§ Out of scope). Android `SAVE_STATE` waits ≤ 1 s while backgrounded.
- **Pillar 3 (never crash)**: a non-corrupt open failure no longer aborts standalone boot or throws across Unreal's C ABI; corruption keeps queued writes (salvage); recreate is refused when it could delete a file another process holds; re-entry is a deterministic throw; launch latches cannot stick or double-release; GPU/CPU/SRV texture leaks, SRV aliasing and use-after-teardown across context recreation are closed; every new path catches and logs; decoders are byte-capped and non-throwing.
- **Pillar 4 (accessibility)**: new text (notice toast, Preferences "Local database" lines, Retry, Opening cue) goes through `T()` keys and the shared theme; Retry is keyboard-reachable; no colour-only signal. UI-thread Lua `get_ticket` now returns nil for tickets not in an open view (documented).
- **Pillar 6 (offline-first)**: the cache now survives restarts from any CWD; `Unavailable` still renders online data and refuses only durable enqueues with a reason; a revalidation reads Refreshing and a failed one CachedStale with the value kept; transitions for another from-status are never shown as live; saved editmeta is project-correct, representative-only and capped at 30 days.

## Risks / non-goals

**Risks**

- **Behaviour change — per-CWD caches converge** into one user-data cache. `--db-path` / `SMATCHET_DB_PATH` keep shell-relative semantics on standalone. Only the best-ranked legacy file is imported; others are named in the notice and Preferences. An older build or a storage-mode switch back keeps its own copy (copy-not-move) — release-noted; the storage-mode switch UI says the database is copied.
- **Edits refused during `Opening`** (normally < 100 ms, up to the busy budget on a contended file) — the refusal names the reason; cue visible.
- **Stale `init-lock` after a crash** — bounded by `BusyBudgetMs` then `UseLegacyThisSession`; the next launch reclaims it (> 120 s).
- **Hidden "Cache ready after Initialize" assumptions** — covered at `CliCommandRunner`, monkey, `UiTestScenario`, `EnsureLocalCacheForUiTest`; every other reader null-guards via `atomic_load`.
- **Longer lock holds (SQ-2)** — one worker operation (10k `GetAllTickets`, a batch, a migration, a 5 s cross-process busy wait) blocks every other caller; bounded for the UI by SQ-0, measured by the bench + tripwire; the click-driven enqueue exception can stall a frame until the follow-up.
- **Re-entry throws at runtime** — internal calls must use the underscored witness forms; the SQ-2 grep and re-entry tests catch regressions. `RunTxn_` bodies re-run on BUSY — the body table is the review checklist.
- **Shutdown raw-pointer race** — `GridContextDepsAdapter::Cache()` hands out a raw pointer (`GridContextDepsAdapter.cpp:40`); a call racing the last `shared_ptr` drop would now destroy a locked mutex (UB). Pre-existing lifetime debt, not fixed here.
- **L3 residuals** — a sleep/NTP jump longer than the lease, a mixed-version pair, a crash-left row within the lease (waits ≤ 120 s at default timeout), a recreate-timeout reopen (new token). `std::random_device` may be deterministic on old MinGW (mixed with `steady_clock` + `this`).
- **SQLite too old for `RETURNING`** — the runtime check throws from the ctor → `Unavailable` (DB-B degrade) instead of every enqueue failing later.
- **Overlay cap (RP-2)** — > 64 saves during one read drops the oldest; the next refresh converges. Cross-namespace contamination ruled out by `{generation, key}` tags + `ClearSavedRows` at both bump sites (tested).
- **Pane-owned restore (RP-4)** — a retired pane restores its last non-empty set after restart (in-session it renders empty); its persisted ids pin those rows in `CollectRetainedByOtherPanes` until it re-syncs or is erased. Needs owner confirmation (Q8).
- **Namespace sweep (RP-5) can delete offline data a user wants** — 90-day age, over-inclusive keep set, queue hold, `isKeyLive` before each chunk; a key going live mid-window loses at most one 500-id chunk (refetched). Queue tables never touched (byte-for-byte test).
- **Legacy files never compacted (RP-6)** — freelist reuse stops growth at the high-water mark; disk space is not returned ("Compact cache" is a future plan).
- **EM network volume** — Jira multi-project warm grows to ≤ min(P·T, 64) + 8 sequential fetches; one GET `/editmeta` per distinct focused Jira row (deduped, backed off). A representative result still stands in for a Done issue on the field-edit path; the 400 → refresh net (`FieldEditPipelineService.cpp:271-285`) is relied on. Upgrade purges legacy `editmeta_type` rows, so a user offline right after upgrade sees optimistic controls until the first warm (safe direction).
- **LS** — an open status combo past the max age briefly shows Refreshing (≤ once per max age per issue; 0 disables); a components list past its max age reads Fresh until the next sync warm; predicates run under `KeyedLookupCache::mutex_` (header rule + review); `learnedErased_` grows by erased triples; `RememberLearned` store writes stay outside the lock (pre-existing).
- **FI** — destruction is delayed ≥ 1 frame + frames in flight (never early); `SmatchetImGuiTextureGuard.cpp:57-64` re-arm depends on the next frame's tick freeing `Destroyed` user textures before Render (comment records it); a missed future `DestroyContext` site leaks (grep check in FI-1 lint step if a zone allows); FI-3 touches the hardened config writer (behaviour preserved verbatim, own PR); 1024-descriptor heap (~32 KiB) must still create on the plugin's minimum-spec RHI; one-time icon + attachment re-download after upgrade (release notes); the FI-7 purge can race new workers or Windows locks (best-effort, per file, logged); `DecodeIconBytesAnyThread` safety depends on `STBI_NO_FAILURE_STRINGS` (`SmatchetImageTextureCache.cpp:10`) and never calling `stbi_set_flip_vertically_on_load` (guard comment).
- **Dual target** — `_WIN32` `PublishNoReplace` / `CREATE_NEW` lock compile in `SmatchetCore_DX12` with no Windows runtime test (covered by `PublishForTest` injection); glibc < 2.28 lacks `renameat2` (`syscall(SYS_renameat2)`, ENOSYS → rename under the lock); new TUs are C++14; Android NDK build for the `android_main` hook; Unreal packaged libs rebuilt per Core PR.
- **Save formats** — all additive (§ Implementation handoff X-list and per-slice schema notes); no DROP/RENAME/retype; older builds ignore new columns, kinds, keys and the `auto_vacuum` header.

**Non-goals**

- Switching `OPEN_FULLMUTEX` to `NOMUTEX`; a DB worker thread; per-thread connections; `ISyncCache` / `ILookupCache` signature changes.
- Salvaging cached tickets, `lookup_cache`, `left_view_history` or `ai_chat_messages` (re-fetched or out of scope); merging two diverged caches after a storage-mode round trip; opening an unwritable-dir cache read-only; persisting `db_path` from Preferences; relocating Android/Unreal paths.
- Sweeping `pending_*` / `*_dead`; trimming `lookup_cache` inside configured namespaces; `VACUUM` / legacy-file conversion; a per-pane cache namespace (ADR-0018 decision 4).
- Changing `LaunchBackgroundTask`'s signature; an age gate on the restored user roster; moving the field-edit pipeline's network calls off the UI thread for palette/Lua.
- Changing `LookupCacheTtlSec` semantics or default; an age input to `ClassifyFreshness`; any change to the components editor gate (`TicketFieldEditor.cpp:390`) or the bulk popup's `fromLive` skip.
- P4 describe persistence; invalidating `file:` texture keys when a local Lua icon changes; a bounded icon worker pool; routing icon fetches through `TrackerHttpClient`; changing the attachment cap or LRU policy.
