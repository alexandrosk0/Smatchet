## Existing utilities reused

Nothing here is a new mechanism — every row below already exists and already does the job; the plan extends or re-points it. Two groups: **reused as-is** (the move is transparent to them) and **reused with a scoped edit** (they carry a hardcoded path or a host-content assumption the flip breaks — the edit is named, not left implicit).

**Reused as-is (no code change; the layout-preserving move keeps them working):**

- `agents/scripts/core/setup-harness.sh` — already the single place that materializes harness adapters (flat per-file hardlinks via `link_agents()`, codex/pi mirrors); the flip only changes its source dir. Note the mechanism is per-file `mklink //H` hardlinks, not a directory junction — a `git submodule update` rewrites layer files to new inodes, so the existing `cmp`-based idempotency probe must be re-run after every update, not only on fresh provision.
- `agents/scripts/core/test-agent-discovery-fixture.sh` — the proven Gate #1 fixture re-run post-flip to prove `.claude/agents` discovery still works through the submodule. Already wired as a `scripts/dev/test-docs.sh` step, so it rides the existing doc-validation lane with no new plumbing.
- `scripts/dev/test-docs.sh` — the canonical local mirror of `doc-validation.yml`; its 19-entry `STEPS` list is the ready-made selector for Phase B's "doc-validation subset" (pick rows from it, don't hand-assemble a new list).
- `agents/scripts/core/test-orphan-bats.sh` — asserts every `tests/bats/*.bats` is named by some `test-*.sh` wrapper under `scripts/dev`, `agents/scripts/core`, `agents/scripts/project`; run in **both** repos it is the free correctness proof for the 61/33 split (a wrapper left behind naming a moved suite, or a moved suite whose wrapper stayed, both trip it).
- `agents/scripts/core/test-markdown-links.sh` — the link enumerator for the Phase C cross-boundary sweep; use it as the enumerator rather than grep (it skips fenced blocks and tier-less plan paths, which a grep sweep gets wrong).
- `.github/workflows/fresh-clone-configure-nightly.yml` — the existing fresh-clone lane; the Phase C fresh-clone proof is a manual run of this lane's steps plus `submodule update --init --recursive`, not a bespoke script.
- `agents/scripts/core/agent_size_audit.py` + `docs/high-integrity/agent-size-baseline.md` — the prompt-size gate and its path-keyed grandfather list travel together with the prompts; only the baseline keys are re-written (Phase C row 16).
- `docs/harness/claude-code/CLAUDE.md.tmpl` — the tracked template `setup-harness.sh` copies to `.claude/CLAUDE.md`; the `@../AGENTS.md` import line to rewrite lives in this file, not inside the script, and it moves to the layer repo in Phase B.

**Reused with a scoped edit (extend, never fork):**

- `scripts/dev/project-config.sh` — already the one config seam; `AGENT_LAYER_ROOT` extends it rather than inventing a second mechanism. Three qualifications the implementer must not skip:
  - It is **deliberately dual-homed**: Phase B row 8 seeds it into the layer repo and Phase C row 11 does not `git rm` it host-side, because a layer-side consumer sources it (`agents/scripts/core/postmortem-owed.sh:160`) *and* a host-side one does (`scripts/dev/with-msvc-env.sh:87`) — those two are the **only** sourcers repo-wide; `agents/scripts/core/setup-branch-protection.sh`, `agents/_shared/skills/git-cleanup-procedures/SKILL.md` and `.github/workflows/doc-validation.yml` merely mention or path-filter it. Two copies in two histories is a fork — so it owes a drift check: a bats case in **each** repo asserting the shared resolution-order block is byte-identical, with the layer copy canonical and the host mirror carried by each bump PR (Phase B row 8g).
  - `PC_CONFIG_FILE` already occupies rung 0 (`PC_CONFIG_FILE="${PC_CONFIG_FILE:-$_pc_root/project.config.json}"`, `:18`; `PC_SCHEMA_FILE` the same at `:42`). `$SMATCHET_PROJECT_CONFIG` must **compose** with it — explicit `PC_CONFIG_FILE` wins, else the three-rung order runs — never silently supersede today's documented escape hatch.
  - `_pc_root` is derived from `${BASH_SOURCE[0]}/../..`, so inside the submodule it resolves to the **layer** root by construction. That is the standalone default the grill decision wants, and exactly why the superproject rung must come first for host callers.
- `agents/scripts/core/merge-gates.sh` + `tests/bats/merge_gates.bats` — reused as the new repo's own gate-poller + its tests, but **not verbatim**. The script derives its required-context config at two sites (`:519`, `:1622`) as `"${MERGE_GATES_CONFIG_FILE:-$SCRIPT_DIR/../../../project.config.json}"` — three levels up from `agents/scripts/core/`. Post-flip that path lands on the **layer's** `project.config.json` even when gating a Smatchet PR, silently degrading the required-absent detector for every host PR. `MERGE_GATES_CONFIG_FILE` is the existing override, but grep confirms only `tests/bats/merge_gates.bats` sets it — no production caller does. Fix (Phase A, before the flip): route both sites through the roots — `PROJECT_ROOT/project.config.json` for host callers, `AGENT_LAYER_ROOT/project.config.json` for the layer's standalone lane — or set `MERGE_GATES_CONFIG_FILE` explicitly at every host invocation site (`git-janitor`, `smatchet-merge-watcher`, orchestrator). Failure mode if skipped is **silent green**, which is why it is a Phase A row and not a Phase C cleanup.
- `agents/scripts/core/is-pure-docs-diff.sh` — extended, not duplicated, for pointer-bump classification. Concretely: the current allow-list is `allow='^(docs/|backlog/|agents/scripts/|.*\.md$)'` (`:53`) and it matches neither the bare gitlink path `agent-layer` nor `.gitmodules`, so today a bump PR exits 1 and drags the full build gate. Extend to `^(docs/|backlog/|agents/scripts/|agent-layer$|\.gitmodules$|.*\.md$)`; docs-tier classification skips the **build**, never the gates — `agent-layer-integration.yml` still binds.
- `agents/scripts/core/check-harness-provisioned.sh` — already the "is `.claude/` wired" probe with a `--selftest` and documented exit codes; extend its existing shape with the empty-`agent-layer/` guard rather than writing a second probe. It has no content-hash check today, so it detects **absence** only — a stale hardlink after `submodule update` is invisible to it, which is why the setup-harness re-run (above) is a separate obligation.
- `agents/scripts/core/plan-lock-gate.sh` + `agents/scripts/core/lock-table-cache.sh` — the fail-CLOSED CI net is reused unchanged in shape, but it self-locates its library as `lib="$root/agents/scripts/core/lock-table-cache.sh"` with `root="$(git rev-parse --show-toplevel)"` and hard-`exit 1`s when that file is missing. Post-flip on the host that path is gone, so the lib resolution (and `LTC_PROJ`, which must stay `PROJECT_ROOT` because the lock table describes `docs/plans/`) is a required Phase A edit for the whole `lock-*.sh` family.
- `agents/scripts/core/test-portable-purity.sh` + `docs/high-integrity/portable-purity-baseline.txt` — the purity gate already scopes to exactly the four PORTABLE dirs (`agents/core`, `agents/_shared`, `docs/agent-rules`, `docs/harness`) that move, so its scope needs no edit; its **denylist is generated from `project.config.json`** (`project.name`, `env_prefix`, `project.literals`, presets, p4 streams). Run self-hosted with the layer's own config the denylist becomes layer literals and the gate stops seeing `Smatchet` leakage entirely — so the layer-side run must point `PC_CONFIG_FILE`/`$SMATCHET_PROJECT_CONFIG` at a Smatchet-literal config, or the host-side run stays the authoritative one.
- `scripts/dev/worktree.sh` — the real worktree creator (`cmd_new()`, the `git worktree add` calls at `:179`/`:181`); `scripts/dev/new-session.sh` only delegates to it, and `bash scripts/dev/worktree.sh new <slug>` is independently documented in `docs/harness/SETUP.md` and `docs/agent-rules/process-rules.md`. The `submodule update --init --recursive` hook therefore belongs in `cmd_new()`, so both the `nsc` wrapper and the documented one-liner get it.
- `docs/PORTABILITY.md` § External path contracts — the pre-existing consumer inventory this plan's Phase A checklist starts from, treated as a **seed, not ground truth**: its line-number citations have already rotted (it cites `test-backlog-counts.sh` lines 32-33 / 40-49; the live file has `INDEX`/`DIR` at 36-37 and the `declare -A FILES` map at 41-51), and its `setup-harness.sh` row still describes a `link_dir ".claude/agents" "agents"` call that no longer exists. Phase A re-verifies every row against the live file before acting on it, and fixes the table in the same PR.

### Stop conditions

Any of these halts the phase rather than being worked around: a `test-docs.sh` step that disappears from the run instead of failing; a layer-side gate that passes only because it is scoped to layer content that never contained the thing it checks (portable-purity with a layer-derived denylist is the known instance); `agent-layer-integration.yml` absent from a bump PR's check list; or a rollback rehearsal that cannot restore a green tree.
