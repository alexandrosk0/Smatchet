## Phase D — process + docs

17. `docs/agent-rules/ship-loops.md` (now in the new repo) — new § Two-repo ship-loop. Four sub-sections, each carrying the exact command, not prose:
    - **(a) Steady-state edit flow (post-merge path).** (1) branch + edit + push in `the-unwilling-agentic-bunch`; (2) that repo's own gates run (`agentic-selftests` over the 61 moved suites, `shell-lint`, the doc-validation subset, `merge-gates.sh` self-hosted); (3) squash-merge there; (4) `auto-bump.yml` (row 18) opens **or updates** the Smatchet PR `chore(agent-layer): bump to <sha>`; (5) `agent-layer-integration.yml` (row 12b) is the binding host check on it; (6) merge the bump PR. State the invariant in bold: **nothing is live for Smatchet until step 6** — a layer merge alone never changes host behaviour, so "it's merged" is never an answer to "is the fix in?".
    - **(b) Pre-merge dev-loop — validating an unmerged layer change against real host content.** Two supported shapes, both documented because step (2) above only proves the layer against *itself*:
      - *Local (default, no PR).* From a host worktree: `git -C agent-layer fetch origin <layer-branch>` then `git -C agent-layer checkout <sha>`; run the host gates (`bash scripts/dev/pre-ship.sh`, `bash agent-layer/agents/scripts/core/check-harness-provisioned.sh`). Revert with `git submodule update --checkout --force -- agent-layer` — restores the pinned SHA; `git checkout -- agent-layer` alone only resets the index entry and leaves the submodule HEAD detached at the WIP SHA. **Never `git add agent-layer` during this loop**: a stray gitlink write turns a scratch validation into an accidental bump commit that then races auto-bump's PR.
      - *Host draft PR pinning a layer branch SHA.* When the evidence must come from real runners (proving `setup-harness.sh` still provisions through the submodule, or that a rewired script resolves both roots in CI), commit the gitlink onto a **draft** Smatchet PR titled `chore(agent-layer): WIP pin to <layer-branch>@<sha>`. Constraints, all failure modes seen in this shape: the SHA must be pushed to the layer remote under `refs/heads/*` or the runner's `submodule update --init` cannot fetch it; **deleting the layer branch after its merge orphans the pin** and reds the draft — re-pin to the merged SHA first; a WIP pin must never leave draft, because two open PRs both moving the gitlink conflict on every rebase and the auto-bump PR is the authoritative one.
      - Consequence for row 12b: `agent-layer-integration.yml` ships `workflow_dispatch:` **in addition to** its `paths:` filter, so the lane can be fired against an arbitrary branch during this loop. Without it, pre-merge host validation is local-only.
    - **(c) Gate matrix — what runs where.**

      | Change | Layer-repo gates | Host gates |
      |---|---|---|
      | Layer content edit (prompts, scripts, rule-docs) | `agentic-selftests` (61 suites) · `shell-lint` · doc-validation subset · self-hosted `merge-gates.sh` | none until the bump |
      | Pointer bump (gitlink only) | none | `agent-layer-integration.yml` (binding) · CodeRabbit · user-comment + Bugbot gates · build skipped via row 17b |
      | Host content edit (plans, entries, `Source/`) | none | unchanged from today |
      | WIP draft pin | none | `agent-layer-integration.yml` via `workflow_dispatch` |

    - **(d) Acceptance.** The section names, per step, the command and the failure it prevents; and `agent-layer-integration.yml` is demonstrated firing + passing on a synthetic pointer-bump PR (§ Verification) **before** `auto-bump.yml` is enabled — enabling automation ahead of its binding check is the exact blind spot grill decision 3 exists to close.

17b. `agents/scripts/core/is-pure-docs-diff.sh` (layer repo post-flip) — extend the allow-list so a pointer-only bump classifies docs-tier:
     `allow='^(docs/|backlog/|agents/scripts/|agent-layer$|\.gitmodules$|.*\.md$)'`.
     Today's `allow='^(docs/|backlog/|agents/scripts/|.*\.md$)'` (line 53) matches **neither** the bare gitlink path `agent-layer` that `git diff --name-only` prints for a submodule-pointer change **nor** `.gitmodules`, so every bump PR exits 1 and drags the full `test-all.sh` build gate — ~6/day, against the low-friction framing of grill decision 5. Anchor both new alternatives with `$`: unanchored, `agent-layer` would also whitelist a root file named `agent-layer-notes.txt`. Docs-tier classification skips the **build**, never the gates — `agent-layer-integration.yml` still binds. **Acceptance**: bats cases asserting exit 0 for a diff whose only entry is `agent-layer`, exit 0 for `agent-layer` + `.gitmodules`, and exit **1** when any non-allow-listed path rides along (a bump PR that also edits `Source/` must not be docs-tier). **Chicken-and-egg**: the first bump PR carrying this fix rides the full build gate itself — one-time, harmless.

18. New layer-repo workflow `auto-bump.yml` — on every merge to the layer's default branch, opens/updates the `chore(agent-layer): bump to <sha>` PR in Smatchet (grill decision 5). Shape modelled on the proven two-token split in `.github/workflows/locks-render.yml`:
    - **Trigger + concurrency**: `on: push: branches: [develop]` in the layer repo (fires post-squash-merge) plus `workflow_dispatch:` for manual recovery. `concurrency: { group: agent-layer-auto-bump, cancel-in-progress: false }` — runs must **serialize, not collapse**; cancelling mid-flight can drop the newest SHA and leave the pin behind with no red anywhere.
    - **Permissions + token**: `permissions: { contents: read }`. The layer repo's `GITHUB_TOKEN` has **zero** rights on Smatchet, so both the branch push and the PR create need `secrets.AGENT_LAYER_BUMP_PAT` — a fine-grained PAT scoped to Smatchet alone with `contents: write` + `pull-requests: write` (user provisions — pause exception 3; naming follows the existing `PLAN_INDEX_PAT` / `LOCK_RENDER_PAT` convention). Carry `locks-render.yml`'s PAT-preflight step over verbatim: probe `gh api -i "repos/<owner>/Smatchet/pulls?per_page=1"`, translate a 401 into an error naming the secret + its rotation procedure, and warn at ≤14 days from the `github-authentication-token-expiration` response header. That step exists because a lapsed PAT produced 23 consecutive red crons logging only a bare 401; the identical failure mode applies here.
    - **Stacking semantics — a second layer merge while a bump PR is open.** Invariant: **at most one open bump PR, ever.** Each run force-recreates the single bot-owned branch `bot/agent-layer-bump` off Smatchet's *current* `develop` tip, writes the new gitlink, force-pushes, then `gh pr list --repo <owner>/Smatchet --head bot/agent-layer-bump --base develop --state open --json number` decides create-vs-amend — **every** host-targeting `gh` call in this workflow (`pr list`, `pr create`, `pr edit`) carries an explicit `--repo <owner>/Smatchet`, because the workflow runs *in the layer repo*, so `gh`'s implicit repo is the layer and an omitted flag queries the wrong repository, finding zero open PRs and creating a duplicate on every run — **no `|| true`** on that query (a failed API call must abort, not create a duplicate; that exact conflation already bit `locks-render.yml`). A second merge while PR #N is open rewrites #N's head to the newer layer SHA and refreshes title/body via `gh pr edit`. Net effect: one PR, always pinning the layer tip, always rebased onto the current develop tip — strictly stronger than "one PR per layer merge", and it removes the stacked-gitlink conflict class entirely. Per-merge firing (decision 5) is unchanged; only the *PR count* coalesces.
    - **Gitlink write without cloning the submodule**: `git clone --filter=blob:none --branch develop <smatchet-url> host` → `git -C host update-index --cacheinfo 160000,<sha>,agent-layer` → `git -C host commit`. No submodule checkout on the runner. Fallback if the index entry is absent: `git -C host submodule update --init agent-layer && git -C host/agent-layer fetch origin <sha> && git -C host/agent-layer checkout <sha> && git -C host add agent-layer`. Do **not** shallow-clone (`--depth=N`) — force-pushing from a shallow clone can be rejected server-side.
    - **Pre-flight guards** (each aborts *before* touching the branch): (i) the SHA is reachable on the layer remote — `git merge-base --is-ancestor <sha> origin/develop`; (ii) the SHA differs from the current pin — `git -C host rev-parse HEAD:agent-layer` — so a merge that leaves the tree identical (e.g. a revert restoring the pinned tree) never opens an empty PR.
    - **PR body**: the layer-side `compare/<old-sha>...<new-sha>` link plus the merged PR titles in that range, so a host reviewer can see what they are pinning without leaving the PR. Refreshed on every amend.
    - **Interaction with host auto-merge**: the bump PR is NOT self-improvement-exempt and rides normal gates; under a standing `governance.auto_merge: on` grant it squash-merges itself once `agent-layer-integration.yml` + CodeRabbit are green, making the steady-state loop hands-off. Under `auto_merge: off` it waits for the post-ship menu or the janitor.
    - **Documented failure modes** (comment them at the workflow): PAT expiry (preflight names it); Smatchet `develop` branch-protected against the bot (PR route only — never a direct push, and never `--admin`); a bump PR open >24h is deliberately **not** retried by the backstop (predicate `P4` below is false) — a stuck bump is a human signal, not an automation loop.

18b. `docs/agent-rules/merge-gates.md` — document the **bump-PR gate profile** in one short subsection: which of the four gate conditions a one-line gitlink PR can actually satisfy (CI = `agent-layer-integration.yml` plus whatever `paths:`-unfiltered lanes fire; CodeRabbit typically lands `COMMENTED + 0 actionable` on a gitlink diff; user-comment and Bugbot gates unchanged), and the explicit rule that **no `*-out-of-band` label and no `SKIP_MERGE_GATES` shortcut is sanctioned for a bump PR**. The bump is the only thing binding layer changes to the host; gating it loosely re-opens precisely the blind spot grill decision 3 closed.

18c. `agents/core/git-janitor.md` + `agents/_shared/skills/git-cleanup-procedures/SKILL.md` — add the **backstop bump proposer**. This is new behaviour, not a re-description: the janitor's current contract (§ Pre-flight, § Standard cleanup loop, § Mutations applied) is single-repo cleanup of *already-open* PRs with no pin comparison, no cross-repo query, and no PR-authoring step. Add it as a closeout cross-check (skill § Pre-flight cross-checks; the agent doc keeps the judgment + the halt conditions). Four predicates, **all** must hold before it proposes:
     - `P1` layer tip resolvable — `layer_tip=$(git ls-remote <layer-url> refs/heads/develop | cut -f1)` non-empty. Network failure ⇒ skip silently; never propose blind.
     - `P2` host pin readable — `pinned=$(git ls-tree origin/develop agent-layer | awk '{print $3}')`. Empty ⇒ pre-flip tree, predicate inert, whole step a no-op (so this can ship before Phase C).
     - `P3` `[ "$layer_tip" != "$pinned" ]` **and** `pinned` is an ancestor of `layer_tip`, tested in a cached layer clone. Fetch both objects into that cache **first** — `git -C "$cache" fetch --no-tags origin develop && git -C "$cache" fetch --no-tags origin "$pinned"` — because a stale (or shallow/filtered) cache simply does not have the pinned commit, and `git merge-base --is-ancestor` on a missing object exits **128** (`Not a valid object name`), not 1. Read naively that is indistinguishable from a genuine non-ancestor, so a cold cache would halt the janitor on every run. Branch on all three outcomes explicitly: `0` ⇒ ancestor, proceed; `1` ⇒ layer history was rewritten ⇒ **halt and surface**; anything else ⇒ the fetch or the object lookup failed ⇒ skip silently, exactly like `P1`. Never propose blind.
     - `P4` no open bump PR — `gh pr list --repo <host> --head bot/agent-layer-bump --base develop --state open --json number --jq 'length'` equals `0`, **and** the newest `auto-bump.yml` run is terminal and older than a 20-minute grace window (`gh run list --repo <layer> --workflow auto-bump.yml --limit 1 --json status,conclusion,createdAt`). Otherwise the janitor is racing auto-bump.
     Action when all four hold: **propose only** — open the identically-shaped PR (dry-run mode prints the command instead, per § Dry-run mode). It never merges the PR in the same pass; a janitor-authored bump rides the full gate poll like any other.
     **Scope decision — the janitor stays single-repo per invocation.** It cleans the repo named by its `--repo`/`GH_REPO` context; layer-repo PR + branch cleanup is a *second* invocation against `the-unwilling-agentic-bunch`, run at closeout when the session touched both. No cross-repo branch deletion from one pass — the shared-account hazard behind § Hard refusals applies unchanged across the boundary.

20. `docs/agent-rules/process-rules.md` § Concurrent interactive sessions — worktree + submodule discipline. Five rules, each with its command:
    - **Provisioning belongs in `scripts/dev/worktree.sh` `cmd_new()`**, immediately after the `git worktree add` calls — not only in `new-session.sh`. `bash scripts/dev/worktree.sh new <slug>` is independently documented as a directly-invocable one-liner (`docs/harness/SETUP.md`; this same process-rules section), so a hook wired only into the `nsc` wrapper leaves a sanctioned entry point producing an empty `agent-layer/` — which then trips `check-harness-provisioned.sh`'s own empty-layer guard on a fully legitimate workflow.
    - **Each worktree gets its own independent submodule clone, not shared storage.** Git nests it at `<main>/.git/worktrees/<slug>/modules/agent-layer` — one level *deeper* than the usual `.git/modules/agent-layer` — and `git submodule update --init` there performs a real clone, not a link. Budget it: one extra clone per `nsc`, plus one more path-depth level for every file in the layer tree. Verify with `git -C <wt>/agent-layer rev-parse --git-common-dir`.
    - **Never write under `agent-layer/` from a host session** — `submodule update` discards it (§ Risks). Layer edits happen in a checkout of the layer repo, via row 17's flow.
    - **Refresh the harness adapter after every `submodule update`.** `.claude/agents` is per-file *hardlinks* into the layer tree; a submodule update writes new inodes, so the links keep resolving to the pre-update content. Rule: any `git submodule update` in an existing worktree is followed by `bash agent-layer/agents/scripts/core/setup-harness.sh claude-code`, whose cmp-based idempotency probe relinks.
    - **HEAD-drift guard extends to the gitlink.** The SessionStart baseline records `git rev-parse HEAD:agent-layer` alongside `{branch,sha}`; a changed pin mid-session means someone bumped underneath the session and the adapter refresh above is owed. Recovery order: `bash scripts/dev/worktree.sh resync` → `git submodule update --init --recursive` → the `setup-harness.sh` re-run.

20b. `docs/agent-rules/process-rules.md` § Git/p4 discipline — extend the 5-step destructive-op pre-flight to submodule operations. `git submodule deinit -f`, `rm -rf .git/modules/<name>`, and `git submodule update --force` are destructive against uncommitted layer content **and** against sibling worktrees' nested module dirs; they get the same pre-flight as `reset --hard` / `clean -f` / `branch -D`, and the same "never on a worktree this session didn't personally check out" rule.

20c. `docs/agent-rules/process-rules.md` — record the **`scripts/dev/project-config.sh` two-copy sync obligation** the split creates (Phase B row 8 seeds it into the layer repo; the host keeps its copy — both are genuinely required: the layer needs a loader when standalone, the host needs one *before* the submodule is initialized). Process rule (Phase B row 8g is the authority): the **layer copy is canonical**; the host copy is a byte-identical mirror. Edit direction is layer-first — a layer PR changes the canonical copy, the bump PR carries the mirrored host copy in the same diff. The expected divergence (host `AGENT_LAYER_ROOT=agent-layer` vs the layer's self-hosting `PROJECT_ROOT=$AGENT_LAYER_ROOT`) lives in `project.config.json` § paths (row 12's config form), not in the script — which is what makes byte-identity achievable. Enforced by the 8g drift gate, which covers **every** mirrored path and not just this one: a `cmp -s` loop over the committed `docs/mirrored-paths.txt` (which also lists the lane runners `scripts/dev/test-all.sh` and `scripts/dev/test-docs.sh`), run as a step in `agent-layer-integration.yml` (the one lane where both trees are checked out, row 12b) plus a host `test-docs.sh` step, with a completeness assertion that every listed path exists in both trees; the gate reds until the mirror lands. Non-goal: symlinking or generating one from the other — a submodule cannot depend on a file above its own root.

## Risks / non-goals

Each risk states its **trigger** (what makes it happen), **detection** (how it becomes visible — several of these are silent by default, which is the actual danger), and **mitigation**.

- **Two-PR friction for every agent-surface edit** — accepted; independent versioning is the point of the extraction.
  - *Trigger*: every layer edit, at measured traffic ~6 layer commits/day over 3 months.
  - *Detection*: not a failure mode, a cost — visible as bump-PR count in Smatchet.
  - *Mitigation*: batching layer edits into one PR; the per-merge auto-bump workflow (Phase D row 18) with its one-open-PR coalescing; the janitor backstop (row 18c). Keeping entries host-side (grill decision 4) removes the hottest write path (525 commits since Jun 1) from the two-repo dance entirely.
  - *Residual*: a layer change is not live host-side until the bump merges — roughly one gate cycle of lag. Urgent host-visible validation uses row 17's WIP draft-pin loop, never a direct write into `agent-layer/`.
- **CI checkout without submodules silently loses the layer** — the dangerous property is that it is *not* a red build.
  - *Trigger*: any `actions/checkout` step lacking `submodules: recursive`, including checkouts performed inside third-party actions.
  - *Detection*: an **empty** `agent-layer/`, so a lane that greps or lints the layer tree passes vacuously — green, and wrong. Nothing else surfaces it.
  - *Mitigation*: `submodules: recursive` added to every checkout repo-wide in Phase A (harmless pre-flip, mandatory after); `check-harness-provisioned.sh` extended to fail loudly on a missing/empty layer dir (Phase A row 5); and `agent-layer-integration.yml` calls that guard as its **first** step, so the one lane that must never pass vacuously cannot.
- **Windows + worktrees + submodules** — the shared-storage assumption is wrong and the long-path mitigation does not exist yet.
  - *Trigger*: every `nsc <slug>` / `worktree.sh new <slug>`.
  - *Mechanism*: `git worktree` does **not** share `.git/modules` for submodules. Each worktree gets its own independent clone nested at `<main>/.git/worktrees/<slug>/modules/agent-layer` — one level deeper than the normal layout — and `submodule update --init` there is a genuine clone (storage + latency per worktree, not a link).
  - *Detection*: `git -C <wt>/agent-layer rev-parse --git-common-dir` shows the nested path; a depth failure surfaces as a clone aborting with `Filename too long`.
  - *Mitigation*: provisioning moves into `worktree.sh cmd_new()` so both sanctioned entry points get it (Phase D row 20); recovery documented in process-rules.
  - *Open, unmitigated*: `core.longpaths` is **not** required by this repo today — zero tracked references anywhere (no `.gitattributes` entry, no `setup-harness.sh` provisioning, no `docs/harness/SETUP.md` step); the only place it is `true` is individual developers' local `.git/config`. The added nesting raises exposure, scaling with worktree-slug length and base-path depth. Mitigation to implement alongside row 20: `setup-harness.sh` sets `git config core.longpaths true` on provision and `check-harness-provisioned.sh` warns when it is unset. Until that ships, this stays an accepted open risk, not a solved one.
- **`project-config.sh` chicken-and-egg** — the layer's scripts need host values; resolved by the resolution order (grill decision 2), with the pre-existing `PC_CONFIG_FILE` override kept as **rung 0, highest precedence**: `PC_CONFIG_FILE` (explicit file) → `$SMATCHET_PROJECT_CONFIG` env → superproject root (`git rev-parse --show-superproject-working-tree`) → layer repo root (the layer's own config, standalone mode).
  - *Trigger*: any layer script sourced from inside the submodule, and every standalone layer-CI run.
  - *Detection*: fail-fast is already built in — the loader exits 2 on a missing required key rather than degrading to empty `PC_*`, so a mis-resolved config is loud, not silent.
  - *Mitigation / escape hatch*: the env rung. Note that a pre-existing override, `PC_CONFIG_FILE`, already exists in the same file and **keeps rung 0, above** the new rungs — a caller naming an exact file is strictly more specific than a root. Phase A row 1a states the composition; the new env rung must never shadow it, or today's documented escape hatch silently stops working. If superproject detection proves flaky on Windows worktrees, fall back to `AGENT_LAYER_ROOT/..` as a last resort. Deviation risk logged here deliberately.
- **`scripts/dev/project-config.sh` forks into two independently-versioned copies** — new risk, and the direct consequence of the row above.
  - *Trigger*: Phase B seeds the file into the layer repo at the same path; Phase C keeps the host copy. Both are genuinely required (the layer needs a loader when standalone; the host needs one *before* the submodule is initialized), so this is not fixable by deleting one.
  - *Failure mode*: a fix to the shared resolution-order logic — including the chicken-and-egg escape hatch above — applied to one copy silently misses the other. Invisible by construction: each repo's tests pass against its own copy.
  - *Detection / mitigation*: Phase B row 8g — the **layer copy is canonical**, the host copy a **byte-identical mirror**, enforced by a `cmp -s` drift gate in `agent-layer-integration.yml` (the one lane where both copies are checked out, row 12b) plus a host `test-docs.sh` step. Byte-identity is achievable because the divergent value (the mount point) lives in `project.config.json` § paths (row 12's config form), not in the script. Edit direction is layer-first: the bump PR carries the mirrored host copy in the same diff, and the gate reds until it does.
- **Delta gates across the move** — the flip PR is a giant delete in Smatchet and the layer repo's history starts at the filter-repo seed; gates that diff `origin/develop` see deletions only (safe). Layer-side gates re-baseline once in Phase B. Rename-tracking (`git log --follow`) works within each repo.
  - *Trigger*: the flip PR itself, then every post-flip PR in either repo.
  - *Detection*: a delta gate that starts reporting *nothing* is the tell — see the next risk, which is the sharp edge of this one.
- **Workflow `paths:` filters go dead silently after the flip** — new risk.
  - *Trigger*: the flip deletes `agents/**`, `docs/agent-rules/**`, `docs/harness/**`, and `AGENTS.md` from the host, but seven workflows carry `paths:` blocks and `doc-validation.yml` names those exact prefixes (`AGENTS.md`, `agents/**`, `docs/agent-rules/**`) plus **14** individual `agents/scripts/core/*.sh` file entries (counted in the live file, not estimated).
  - *Failure mode*: a `paths:` entry that can never match is **not an error**. The lane simply stops firing on that trigger, and the coverage loss is invisible — no red, no warning, no changed check name.
  - *Detection*: a whole-file `git grep` over `.github/workflows` is the wrong instrument — it cannot tell a `paths:` entry from a `run:` line that legitimately invokes `agent-layer/agents/scripts/…`, so it reports false positives forever and gets ignored. The check is **YAML-aware**: parse each workflow, walk only the `on.*.paths` / `on.*.paths-ignore` sequences, and assert no entry starts with `agents/`, `docs/agent-rules/` or `docs/harness/`, or equals `AGENTS.md`. It ships as a host gate script (`test-workflow-path-filters.sh` wrapping a small `yaml.safe_load` walker, same shape as the sibling `test-*.sh` gates) so it keeps firing after the flip instead of being a one-off grep.
  - *Mitigation*: Phase C sweeps every `paths:` block; layer-keyed entries are deleted host-side and re-created in the layer repo's own lanes (Phase B row 9); `agent-layer` + `.gitmodules` are added where the host must still react. `agent-layer-integration.yml`'s filter is the load-bearing one — a typo there silently disables the bump gate, which is why § Verification requires a synthetic bump PR proving the lane fires before auto-bump is enabled.
- **`docs/self-improvement/**` auto-exemption stays host-side** — entries never move (grill decision 4), so Smatchet's `.coderabbit.yaml` path_filter and the `selfImpOnly` Bugbot exemption are untouched; the layer repo's fresh `.coderabbit.yaml` carries no such exemption.
  - *Trigger*: any bump PR, and any layer PR that happens to be docs-only.
  - *Detection*: a bump PR showing as auto-exempt would be the bug — it must ride normal gates including the new integration lane.
  - *Mitigation*: stated explicitly in row 18b; no `*-out-of-band` label and no `SKIP_MERGE_GATES` shortcut is sanctioned for a bump PR.
- **Submodule working tree is not a write target** — anything an agent session writes under `agent-layer/` is discarded by the next `submodule update`; process-rules (Phase D row 20) must say so explicitly. Entries staying host-side removes the main historical writer from this hazard.
  - *Trigger*: `git submodule update`, and especially `--force`, in any worktree.
  - *Detection*: weak by default — the host `git status` shows only `modified: agent-layer (modified content)`, one line that is trivially missed in a long status, and it disappears the moment the update runs.
  - *Mitigation*: the process rule above plus row 17's dev-loop, which gives the two *sanctioned* ways to exercise an unmerged layer change (local detached checkout; WIP draft pin) so nobody needs to write into the tree.
- **Harness hardlinks go stale after a submodule update** — new risk.
  - *Trigger*: any `git submodule update` in an **existing** worktree (a pull, a merged bump, a sibling's bump). Fresh worktrees are covered by row 20's provisioning; existing ones are not.
  - *Mechanism*: `.claude/agents` is populated by `link_agents()` in `setup-harness.sh` as per-file **hardlinks** (`mklink /H`) into the layer tree. A submodule update replaces files with new inodes, so the existing links keep resolving to the pre-update content.
  - *Detection*: **none automated today** — `check-harness-provisioned.sh` has no cmp/diff/hash check; it detects total absence, not stale content. The symptom is an agent silently running a stale prompt, which reads as a model regression rather than a provisioning bug.
  - *Mitigation*: the mandatory `setup-harness.sh` re-run after every submodule update (row 20) — its existing cmp-based idempotency probe relinks correctly once invoked. The content check itself ships in Phase A row 5e (`check-harness-provisioned.sh` reuses `_agents_dir_current()`'s `cmp` probe), so the stale state is *detectable*, not merely fixable.
- **Rolling back the flip is not a plain `git revert`** — new risk.
  - *Trigger*: the flip lands and has to be undone (any Phase C defect discovered post-merge).
  - *Mechanism*: reverting the flip commit restores the deleted files and drops the gitlink from the tree, but leaves three pieces of local residue a revert cannot touch — the `[submodule "agent-layer"]` section in `.git/config`, the module dir `.git/modules/agent-layer` (plus every worktree's nested `.git/worktrees/<slug>/modules/agent-layer`), and the now-untracked `agent-layer/` working-tree dir. Git says so during the revert: `unable to rmdir agent-layer: Directory not empty`.
  - *Recipe* (order matters — `deinit` runs **before** the revert, because it needs the gitlink and the `.gitmodules` entry still in the tree; run afterwards it errors `pathspec 'agent-layer' did not match any file(s) known to git` and cleans nothing): `git submodule deinit -f agent-layer` → `rm -rf "$(git rev-parse --absolute-git-dir)/modules/agent-layer"` → `rm -rf agent-layer` → repeat those three per live worktree, each time deriving the dir as `git_dir="$(git -C "$wt" rev-parse --absolute-git-dir)"` and removing `"$git_dir/modules/agent-layer"` (a literal `.git/modules/…` is simply wrong inside a linked worktree, where `.git` is a *file* pointing at `<main>/.git/worktrees/<slug>/`; `--absolute-git-dir` resolves that indirection in both the main checkout and every worktree, so one form covers all of them) → `git revert --no-edit <flip-squash-sha>` → `probe_rc=0; git config --get-regexp '^submodule\.agent-layer\.' >/dev/null 2>&1 || probe_rc=$?; case "$probe_rc" in 0) git config --remove-section submodule.agent-layer ;; 1) : ;; *) echo "rollback: submodule config probe failed (git config exit $probe_rc)" >&2; exit "$probe_rc" ;; esac` (belt-and-braces, and the cleanup has to discriminate **three** outcomes, not two. Unguarded is wrong: the `deinit` in step 1 already dropped that section, so `--remove-section` exits **128** with `fatal: no such section` and aborts the rollback one step from the end under `set -e`. A blanket `2>/dev/null || true` is wrong in the opposite direction — it swallows a genuine permission, lock-contention or malformed-config failure identically to the benign missing-section case, and the rehearsal then finishes “green” with stale submodule metadata still in `.git/config`. A bare `if git config --get-regexp …; then …; fi` fails the same way, only less visibly: an `if` condition suspends `set -e` for **every** non-zero status the probe can return, so it reads a broken config as an absent section. Measured probe exits: **1** (section absent, no output), **128** (`fatal: bad config line …` — malformed or unreadable config), **6** (invalid regexp). So capture the status rather than test it: `|| probe_rc=$?` suspends `-e` for that one command while the list as a whole still succeeds, and the `case` removes on **0**, skips only on **1**, and re-raises every other status under its own exit code — so a malformed config, a lock-contention failure, or a failing `--remove-section` itself all still stop the rollback where they should) → re-run `bash agents/scripts/core/setup-harness.sh claude-code`. Verify clean with `git config --get-regexp '^submodule\.'` returning nothing and `git status` showing no untracked `agent-layer/`.
  - *Scope*: rollback restores the host only. The layer repo stays published — harmless, since nothing consumes it once the gitlink is gone. Disable `auto-bump.yml` in the layer repo as part of the rollback, or it keeps opening bump PRs against a host with no submodule.
