Smatchet architecture map

Smatchet is one ImGui application core that three hosts embed. A single AppController owns the tracker backends, the SQLite cache and the sync services; every panel reads from it, and every automation surface reaches it through one command registry.

Shape of the build and the frame

Build targets

  • SmatchetStandalone compiles the Core sources straight into the executable; there is no separate core library on the desktop path.
  • Each plugin is a static library (SmatchetPlugin_Mcp, _LuaConsole, _Whisper) behind a CMake switch: SMATCHET_WITH_MCP, _LUA_AUTOMATION, _WHISPER, and _AI for the assistant.
  • The Unreal plugin links a DX12 build of Core and talks to it only through the C API in SmatchetImGuiHostC.

One frame

  • The host calls SmatchetUI::Draw(app), then PluginHost::OnDraw(app), then EndFrame().
  • HTTP, SQLite, p4 and file I/O run on worker threads. Results come back through MainThreadDispatcher, which drains within a per-frame time budget.
  • Panels read immutable snapshots (shared_ptr<const vector<CachedTicket>>) so a draw never waits on a lock held across I/O.

Tracker abstraction

  • ITrackerBackend hands out six role interfaces: Reader, Connectivity, FieldCatalog, Mutations, Collaboration, Activity. The last four may be nullptr.
  • DefaultTrackerBackendFactory builds JiraClient, PlaneClient, GitHubClient or LinearClient from the configured type.
  • Fixture backends run canned JSON through the same mapping code, so tests and scenarios never touch the network.
