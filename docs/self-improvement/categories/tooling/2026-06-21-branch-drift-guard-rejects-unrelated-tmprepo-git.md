- 2026-06-21 · build-doctor (si-guard-scope) · [tooling] · P2 — `branch-drift-guard-rejects-unrelated-tmprepo-git`: the PreToolUse HEAD-drift guard (`docs/harness/claude-code/hooks/guard-head-drift.sh`) false-DENIED `git -C <path> commit` / HEAD-moving ops that target a wholly UNRELATED repository (e.g. a bats fixture driving a `mktemp` throwaway repo: `git -C "$BATS_TMPDIR/repo" commit`), forcing agents onto awkward `SMATCHET_ACK_BRANCH_DRIFT=1` / token-obfuscation workarounds. Flagged independently by ≥4 agents this session.
  Root cause: the guard's exemption helper `all_git_ops_target_safe_worktree` recognised only LINKED WORKTREES of the integration repo (`[ -f "$tgt/.git" ]` — `.git` is a file pointer). A freshly `git init`-ed throwaway repo has a `.git` DIRECTORY, so it failed the linked-worktree test and fell through to the deny — even though it shares nothing with the protected develop/main tree and cannot move this session's HEAD. The branch check made it worse: a tmp repo legitimately on `develop`/`main` looked exactly like a direct-commit-to-protected attempt.
  Fix (applied): added a SEPARATE-REPOSITORY exemption keyed on `git rev-parse --git-common-dir`. The integration tree and ALL its linked worktrees resolve to the same common-dir (`.../main/.git`); a distinct repo resolves to a different one. The per-target loop now resolves the target's absolute common-dir (`git_common_dir_abs`) and compares it to the protected tree's (`PROJ_COMMON`, computed once): if they DIFFER, the op targets an unrelated repo → ALLOW regardless of its branch. If they MATCH (same repo, or either resolution empty → conservative), it falls through to the UNCHANGED linked-worktree + protected-branch checks. Net: only the false-positive on unrelated `-C <elsewhere>` targets is removed; every prior protective case is preserved bit-for-bit.
  Protective cases preserved (verified by the existing 24 bats cases, all still green): bare `git commit` on develop/main in the integration tree → DENIED; `git -C <integration-tree>` commit → DENIED (same common-dir, `.git` is a dir); `git -C <linked-worktree-on-main>` commit → DENIED (same common-dir, protected branch); compound safe+unsafe (`git -C $WT commit && git commit`) → DENIED; PowerShell `git.exe` / quoted call-operator forms → DENIED; drifted-HEAD in-tree HEAD-moving ops (pull/reset/merge/…) → DENIED; spaced-quoted-path parsing (no fail-open); Edit/Write drift deny + worktree exemption; `SMATCHET_ACK_BRANCH_DRIFT=1` override.
