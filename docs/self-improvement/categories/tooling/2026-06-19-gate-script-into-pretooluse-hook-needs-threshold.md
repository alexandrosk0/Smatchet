- 2026-06-19 · orchestrator · [tooling] · P3 — `gate-script-into-pretooluse-hook-needs-threshold-and-own-output-assertions`: promoting a `--strict` gate-script (built for explicit pre-launch invocation, where it flags EVERY instance) into an always-on PreToolUse hook needs a scope threshold or it blocks trivial calls — plus two adjacent gotchas that surfaced wiring it.
  Details: from #1429 (the fleet-preflight `Workflow` PreToolUse hook). Three concrete lessons. (1) THRESHOLD — `fleet-preflight.sh --strict` exits non-zero on ANY warn, and its check 1 flags every unpinned `agent()`, so blocking the Workflow tool on a raw non-zero exit would refuse even a 1-agent helper. The documented MUST is ">2 agents", so the hook must parse the `agent()` count and only block ABOVE that threshold; the gate's own exit code is necessary but not sufficient as a per-call block signal. (2) TEST ASSERTIONS — a hook that ECHOES the wrapped tool's output must assert on its OWN distinctive prefix, not a generic phrase: a bats `[[ "$output" != *"blocking launch"* ]]` false-failed because `fleet-preflight`'s own output also contains "blocking launch"; fixed by asserting the hook-specific `[fleet-preflight-hook] blocking launch`. (3) PORTABLE-PURITY — documenting the hook's `<PROJECT>_*`-prefixed env knobs in the PORTABLE rule-doc (`docs/agent-rules/workflow-fleets.md`) tripped `test-portable-purity` (project-name literal leak); the env-name literals belong in the non-portable hook header, and the portable doc references them generically.
  Concrete next action: when next wiring a gate-script into a per-call PreToolUse/PostToolUse hook, follow this checklist (encode it wherever hook-authoring is documented — the harness `setup.md` or a new `docs/agent-rules` hook note): (a) gate the BLOCK on the documented scope threshold, not the raw gate exit code; (b) make the hook fail-OPEN (missing dep / unparseable payload / wrong tool → exit 0 allow) — a guard that blocks every call when jq is absent is worse than the gap it closes; (c) assert tests on the hook's own output prefix, never a phrase the wrapped tool also emits; (d) keep project-prefixed env-name literals out of portable rule-docs (reference generically, literal lives in the non-portable source). Est: nil beyond the doc note — these are discipline, proven by the #1429 bats.
