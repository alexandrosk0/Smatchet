- 2026-06-20 · claude-code · [tooling] · P2 — `stop-hook-git-check.sh` misfires "Unverified" on SSH-signed commits because `%G?` is `N` (not B/U/E) when no `allowedSignersFile` is configured

  Details: In CCR-web the environment signs commits via an SSH signer (`gpg.format=ssh`, `gpg.ssh.program=/tmp/code-sign` → CODESIGN_MCP) with `user.signingkey` pointing at a **0-byte** `~/.ssh/commit_signing_key.pub` and **no** `gpg.ssh.allowedSignersFile`. A commit IS signed (a real `gpgsig -----BEGIN SSH SIGNATURE-----` blob, committer `noreply@anthropic.com`), but with no local public key and no allowed-signers file, `git log --format=%G?` returns **`N`** and `git log --show-signature` prints "No signature". The stop hook (`~/.claude/stop-hook-git-check.sh:54`, `awk '$2=="N" || $3!="noreply@anthropic.com"'`) treats `%G?=="N"` as missing-signature — its own comment (L50-52) explicitly assumes signed-but-unverifiable commits report B/U/E, which is FALSE for this SSH setup. Result: every commit this session re-triggered the hook with the suggested remedy `git config user.email … && git commit --amend --no-edit --reset-author`, which CANNOT fix it (email was already correct; the signature was present; the gap is purely *local verification*). Confirmed harmless downstream — GitHub verified the commits on push (PR #1462 merged; author mapped to the `claude` GitHub user). Reconstructing an `allowedSignersFile` from the signature's embedded key flipped `%G?` `N`→`B` (passed the hook's `N`-only test but is misleading), so that is not a real fix.

  Concrete next action: harden the hook's presence check — treat a non-empty `gpgsig` header (`git cat-file -p <sha>` / `git log --format=%GG`) as "signed" even when `%G?==N`, so SSH-signed-but-locally-unverifiable commits aren't flagged; OR provision a working `gpg.ssh.allowedSignersFile` (+ the real signing pubkey, not the 0-byte placeholder) in the CCR-web image so `%G?` resolves to G/U. NOTE: this hook is CCR-web-environment-global (`~/.claude/`), **not** repo-owned (`docs/harness/claude-code/hooks/`), so the fix is upstream in the CCR image, not a Smatchet PR — filed here as an observed agentic-infra learning.
