  Details: the gate's `TEST_CHANGES` list is a fixed per-directory glob (`Core/*.test.cpp|Lua/*.test.cpp|Plugins/*.test.cpp|Plugins/Mcp/*.test.cpp|ui/*.test.cpp`). PR #1637 added a genuine new seeded-fuzz harness under `tests/monkey/` (`monkey_command_registry.cpp`, `CommandArgSynth.h`) paired with a behaviour-preserving `Source/Core/src/.../CommandContractSweepScenario.cpp` extraction — but `tests/monkey/*` is invisible to `TEST_CHANGES` AND its `.cpp/.h` lines count as "real surface" in the `_classify_diff` exemption pre-check, so the gate reported `FAIL: Source/Core/ changes without test deltas` despite the PR adding hundreds of lines of tests. Cost a diagnosis round-trip; the workaround was to add a `tests/Core/*.test.cpp` unit test (arguably the right home for the pure logic — so the gate's *nudge* was defensible, but the *surprise* + the fact that a new harness dir carries zero gate credit is the sharp edge). Distinct from the two existing coverage-delta-gate entries: the SIGPIPE-crash fix (#1593, `tooling/2026-07-02-coverage-delta-gate-sigpipe-crash.md`) and the platform-`#else`-arm exemption gap (#1021, `categories/tooling.md`) — both are about the *exemption classifier*; this one is about the *test-file recognition* glob.
  Concrete next action: either (a) broaden `TEST_CHANGES` to recognize any first-party test TU (`tests/*/*.test.cpp`, excluding `tests/support/` and `tests/fixtures/`), so a PR that genuinely adds tests under a new harness dir passes without a decoy `tests/Core` file; or (b) if the intent is that pure logic must live in a bucket-A `tests/Core` unit test, document that in the PR template's "Coverage gate override" section so the nudge is explicit rather than a surprise red. Prefer (a) — it removes an incentive to add a token test in the wrong place just to satisfy the pattern.
