- 2026-06-19 · orchestrator (gate-escape postmortem, PR #1428) · [tooling] · P1 — the `smatchet-merge-watcher` daemon runs `merge-gates.sh` from its own long-lived host checkout, so a daemon started days ago silently enforces STALE gate logic (block-allowlist / CI rules) that has since changed on `develop`. It merged #1428 past a red block-allowlisted `Intent section` check because its checkout predated the #1391/ADR-0022 allow-list addition; the poller *was* consulted but ran two-day-old rules, and the `merge-snapshots.jsonl` audit row (written by the stale poller itself) self-reported `redChecks:[]`, so the audit trail cannot detect its own staleness.
  Details: the watcher (`agents/scripts/core/merge-watcher.py`, Scheduled Task `SmatchetMergeWatcher`) ran `merge-gates.sh` from the integration tree `C:/Dev/Smatchet`, parked on a branch predating #1391. `Intent section` was added to `MERGE_GATES_BLOCK_ALLOWLIST_RE` on 2026-06-18 (#1391, ADR-0022); the daemon's blob predated that, so its regex did not match `Intent section` → a non-required RED treated as advisory → `GATES_PASSED`. Distinct from the #1406/#1414/#1415 escape (poller never consulted; remedy = poll-gated merge wrapper) — here the poller WAS consulted, so a wrapper would invoke the same stale poller and not catch it.
  Preventing gate (applied): a gate-logic self-freshness guard in `agents/scripts/core/merge-gates.sh` — before emitting `GATES_PASSED` it compares the git blob of its own running file against `origin/develop`'s blob for the same path and, on divergence (or when unverifiable), refuses `GATES_PASSED` fail-closed. Gated by `MERGE_GATES_FRESHNESS` ∈ `{off (default) | warn | block}`; `merge-watcher.py` sets `block`; default `off` leaves existing callers + local-dev unaffected. Backed by 5 bats cases (off-inert, block+stale→refuse, block+fresh→pass, warn→warn-only, block+unverifiable→fail-closed).
  Residual (operational): a self-guard cannot retro-protect a daemon already running the pre-guard file, so the stale daemon was stopped + its Scheduled Task disabled (fail-safe), to be restarted only from an up-to-date `develop` checkout, plus a periodic daemon self-resync. That operational restart-from-fresh-checkout step is the open residual.
