- 2026-06-21 · build-doctor (P3-sweep surfaced) · [tooling] · P3 — `std::numeric_limits<T>::max()`/`min()` deterministically breaks the MSVC build via the `windows.h` `max`/`min` macros (C4003/C2589/C2589)
  Details: surfaced in PR #1527 — adding `std::numeric_limits<std::size_t>::max()` to a TU that transitively includes `windows.h` fails to compile because `windows.h` defines `max`/`min` function-like macros that mangle the `::max()` call. Recurring + deterministic; not in build-doctor's Common-causes list. The fix is to parenthesize: `(std::numeric_limits<T>::max)()` (the extra parens defeat the macro), or `#define NOMINMAX` before `windows.h` where feasible.
  Concrete next action: add a one-line entry to build-doctor's Common-causes (`agents/core/build-doctor.md` or the linked cpp-rules build doc): "MSVC C4003/C2589 on `numeric_limits<T>::max()/min()` → wrap as `(std::numeric_limits<T>::max)()` to defeat the `windows.h` `max`/`min` macros." Optionally a WARN-first grep lint for bare `numeric_limits<...>::max()`/`min()` (no surrounding parens) in TUs that include windows.h.
