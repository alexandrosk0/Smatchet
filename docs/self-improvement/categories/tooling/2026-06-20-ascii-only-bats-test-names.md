  Details: every C++/tooling agent in the roadmap campaign independently hit this: `bats` 1.13 on the Windows host emits `bats: unknown test name $'...\342...'` for a `@test` title containing a Unicode arrow / em-dash, SKIPS that case, and counts the batch as a single "Failed: 1" / "Executed N instead of M" — NOT an assertion failure. A wrapper counting `ok`/`not ok` reads it as pass-with-fewer-tests. Confirmed live in `tests/bats/merge_watcher.bats` (~20 self-resync tests with `→` names never run on this host), `postmortem_owed.bats`, `merge_gates.bats`. CI's Linux bats parses Unicode fine, so the skipped tests DO run in CI — but local pre-push verification silently under-runs, masking real local failures. This is the exact class the orphan-bats gate was built to prevent (authored tests that never run), one layer down.
  Concrete next action: (1) add an absolute-0 lint over `tests/bats/*.bats` (+ `agents/scripts/**/*.bats`) banning non-ASCII in `@test` titles (`grep -nP '^@test .*[^\x00-\x7F]'`), WARN-first then blocking, with `--selftest` + the `# selftest: asserts-failure` marker; (2) a one-time ASCII-rename sweep of the ~20 existing offenders (arrows/em-dashes are fine in comments + Status prose — only `@test` TITLES must be ASCII).
