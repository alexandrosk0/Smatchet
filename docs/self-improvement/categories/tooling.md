- 2026-06-02 · orchestrator · [tooling] · P3 — `comment_audit.py` noise heuristics false-positive on ordinary prose (the #1 build-green-but-CI-red cause; ~10 fix-commits this program)
  Details: Across the function-size program the comment-noise gate caused ~10 separate fix-commits, every one a false positive on legitimate doc prose. `CODE_LIKE_RE` (in `comment_audit.py`) flags a comment when its body (a) contains a `word (` adjacency (e.g. `// Returns Apply (with working set)…`, `// match SmatchetMcpServerUi.cpp (the only caller)`), (b) ends in `;`/`)`, or (c) starts with a C++ keyword (`if`/`for`/`else`/`return`); and `comment-blank-run` flags ANY bare `//` separator line inside a multi-line comment block. Net effect: subagents repeatedly shipped build-green branches that failed CI on a comment, costing a CI round-trip + fix-commit each.
  Concrete next action: (1) tighten `CODE_LIKE_RE` — require higher code-token density, and treat a comment line ending in sentence punctuation (`.`/`!`/`?` after a word) as prose regardless of an interior `(`/`;`. (2) normalize leading whitespace before the `--diff` snippet comparison so a re-indented-but-byte-identical comment stays grandfathered. (3) Mandate `scripts/dev/pre-ship.sh` (shipped #746) as the last pre-push step everywhere — it enforces the correct clang-format-THEN-gate order so a reflow can't slip a comment past.
