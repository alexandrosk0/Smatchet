  Details: A bare `gh pr merge --squash --auto` waits only on GitHub-*required* check contexts. The CodeRabbit, user-comment, and conversation-resolution gates are NOT GitHub-required, so bare `--auto` is wrong in BOTH timing directions: (1) it can COMPLETE the merge BEFORE CodeRabbit even posts its async review — merging past a real CR finding (the #1332 merge-beats-review race class, on the non-admin path); and (2) it WEDGES forever on a stuck CR-findings / `require_conversation_resolution` BLOCKED state — it neither merges nor explains why. `safe-merge.sh` runs the FULL merge-gates poll (CR + user-comment + conversation) before arming `--auto` ONLY on `GATES_PASSED`, and refuses on any block-allowlist RED lacking its named `*-out-of-band` override label; `scripts/dev/pr-blocked-why.sh <pr>` names the precise blocker for the wedge case. The rule existed implicitly (the wrappers shipped) but the race+wedge rationale was not captured as an explicit dogfood rule in the ship-loop / merge-gate docs.
