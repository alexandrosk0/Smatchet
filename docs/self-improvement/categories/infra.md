- 2026-06-04 · orchestrator · [infra] · P3 — Lua is the one dependency fetched over plain HTTP (`file(DOWNLOAD)`), not an immutable git ref — single upstream SPOF
  Details: Every Smatchet dependency is a pinned git ref (FetchContent `GIT_REPOSITORY` + `GIT_TAG`) **except** Lua 5.3.6, which `CMakeLists.txt` pulls as a tarball over HTTP from `lua.org` (no git ref / checksum companion published upstream). A `lua.org` outage on 2026-06-04 timed out the `file(DOWNLOAD)` and red-walled all four MSVC builds on `develop` for hours. Mitigated (PR #840: github mirror primary + lua.org fallback + retry + post-download hash-verify), but the plain-HTTP fetch remains the only non-git-ref dep and the structural SPOF — the mirror is a patch over it, not removal.
  Concrete next action: migrate Lua to a proper git ref like every other dep — either FetchContent against a github Lua-source mirror at the `v5.3.6` tag (note: codeload git-archive tarballs are hash-unstable, so verify by content not by pinning the archive sha), or a vendored git submodule. Removes the HTTP fetch + the bespoke mirror/retry block entirely. Estimated cost ~1-2 h (find a byte-stable github source, rewire the fetch + the Lua-as-C++ `luaconf.h` patch, verify both targets build). Low priority — #840's mirror already removes the immediate fragility.
