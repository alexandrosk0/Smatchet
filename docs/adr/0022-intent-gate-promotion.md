# Promote the PR `## Intent` gate via the merge-gates allow-list, not branch protection

When promoting the advisory `Intent section` CI check to merge-blocking (`docs/plans/pr-intent-capture-hardening.md` #5), we route it through the `merge-gates.sh` meant-to-block allow-list (`MERGE_GATES_BLOCK_ALLOWLIST_RE`, the same mechanism that blocks `Coverage`/`Sanitizer`) plus an `intent-out-of-band` override label — rather than adding it to `project.config.json` `branch_protection.required_contexts`. We chose this because the allow-list path is reversible (one regex alternation + a rename) and avoids the merge-queue deadlock class documented in `docs/agent-rules/merge-gates.md`:83, where a branch-protection required check that never reports on the `merge_group` ref blocks the queue forever; the rejected required-contexts alternative would have been strongest but hard to reverse and would have required wiring the `pull_request`-only Intent job to also report on `merge_group`. The `intent-out-of-band` label (same never-pre-apply hygiene as `tests-/perf-/cr-out-of-band`) covers the fresh-worktree and non-Claude-Code fallback flows that legitimately can't auto-capture, since capture-on-prompt is Claude-Code-only across the harness matrix.
