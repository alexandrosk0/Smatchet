# Smatchet — Principal Architecture Review (WITH agents.md governance layer)

## 1. Executive Summary + Verdict

Smatchet is a C++14 desktop/embeddable issue-tracker client (Jira / GitHub / Linear / Plane backends, Dear ImGui UI, dual GLFW-GL3 + DX12 render targets, SQLite offline-sync, Lua/MCP/CLI automation). Read **as code alone** it is a competent, above-average application architecture with one classic smell (a 1465-line `AppController` god-header with 117 includers). Read **with its agentic-governance meta-layer** — the dimension this review centers — it is something materially rarer: a codebase whose architectural rules are **executable, machine-checked invariants** rather than prose, with a delta-gated ratchet that prevents regression and a per-subsystem `AGENTS.md`-as-ADR layer that keeps design intent co-located with the code it governs.

The headline finding is that **the governance layer is itself the most load-bearing architectural artifact in the repository.** The include graph is provably a clean layer-DAG (the `include_cycle_audit.py` gate confirms 0 violations across 2026 first-party edges, with an explicit numbered layer ranking Ui=6 > AppController=5 > Commands=4 > Tracker=3 > Sync/Persistence=2 > Config=1 > leaf=0). The `ITrackerBackend` abstraction is a textbook ISP decomposition. The god-object is not hidden debt — it is a *named, measured, ratcheted, actively-decomposed* line item with a 200-line decomposition plan and four already-shipped service extractions. The baselines function as an honest debt-ledger that the code alone would obscure.

**Verdict: this is a strong architecture (7.5/10 code; 9/10 governance) whose distinguishing achievement is proving that "architecture as enforced invariant" both works and outperforms conventional architecture docs for integrity-over-time — at a real and non-trivial meta-layer maintenance cost that a solo maintainer is currently absorbing.** The single biggest *code* risk (AppController) is the single best-governed risk; the single biggest *meta-layer* risk is the cognitive surface area of the governance system itself.

## 2. Scope & Method

I read the governance meta-layer as a first-class subsystem alongside the code: root `AGENTS.md` (28 KB navigation contract), `AI_POLICY.md` (human-authority charter), `CONTEXT-MAP.md`, `docs/STRUCTURE.md`, `project.config.json` (the single project-value seam), the five per-subsystem `Source/Core/src/*/AGENTS.md` leaf docs, `docs/high-integrity/**` baselines, `docs/adr/**` (22 ADRs), `docs/self-improvement/**` (debt + 255-entry postmortem ledger), `docs/agent-rules/cpp-rules.md`/`quality-pillars.md`, and the audit scripts (`include_cycle_audit.py`, `appcontroller_fan_in_audit.py`, `dup_audit.py`, `function_size_audit.py`). On the code side I read the `ITracker*` role interfaces, `AppController.h`, the Commands registry, the 126 KB `CMakeLists.txt`, the Standalone bootstrap, and ran the include-cycle + fan-in audits live to verify claims against the tree rather than the docs. Citations are `file:line` and doc-relative.

## 3. System Decomposition & Layering

The system decomposes into a portable **`SmatchetCore`** (the `SmatchetCoreInterface` INTERFACE library, `CMakeLists.txt:1272`) consumed by three render/host targets — `SmatchetStandalone` (GLFW/GL3 exe, `CMakeLists.txt:1831`), `SmatchetCore_DX12` (`EXCLUDE_FROM_ALL`, Unreal-embedded, `:1499`), and `SmatchetMobile` (Android SHARED lib, `:1520`). Core itself is layered by directory, and — critically — that layering is **not aspirational**: it is encoded as integer ranks in `include_cycle_audit.py:14-26` and enforced as a back-edge gate.

The internal layering, high-to-low: `Ui/` → `AppController` → `Commands/` → `Tracker/` → `Sync/`+`Persistence/` → `Config/` → leaf headers. Dependencies must flow high-to-low; any low→high include edge or any strongly-connected component > 1 node fails the gate. The live audit reports a **clean DAG** (`include_cycle_audit.py` output: "resolved first-party edges: 2026 … violations: 0"). The grandfather baseline (`docs/high-integrity/include-cycle-baseline.md`) lists **0 grandfathered edges** — meaning the layering is not just frozen-in-place, it has been driven to genuine acyclicity, not merely capped.

One subtle and well-reasoned ranking decision: `AppController` ranks *above* `Commands` (5 vs 4) even though they feel peer-level, because `Commands/MainThreadDispatch.h → AppController.h` is a real back-edge the gate must catch and it would be invisible under a coarse same-layer grouping (`include_cycle_audit.py:18-21`). This is the kind of distinction prose ADRs routinely get wrong and a graph gate gets right.

Plugin gating is compile-define driven (`SMATCHET_WITH_AI`, `_LUA_AUTOMATION`, `_MCP`, `_MCP_UNREAL`, `_WHISPER`), with a dedicated "light" CI lane (`Windows + MSVC (Smatchet light — AI/Whisper/MCP off)`) that proves the feature-OFF build compiles — and a calibration lint (`unused-symbol-under-config-guard`) that catches the classic "function dead in the OFF build → `-Werror,-Wunused-function`" config-skew (the #863 class).

## 4. Load-bearing Abstractions (evidence)

**`ITrackerBackend` (the standout).** `Source/Core/include/ITrackerBackend.h` is a 23-line capability-aggregate that segregates six narrow role interfaces: `Reader()` and `Connectivity()` are mandatory (`= 0`), while `FieldCatalog()`, `Mutations()`, `Collaboration()`, `Activity()` return nullable pointers ("nullptr if unsupported"). This is **Interface Segregation done correctly**: a fixture backend implements only what it supports; `JiraClient`/`GitHubClient`/`LinearClient`/`PlaneClient` light up capabilities incrementally. The role interfaces themselves (`ITrackerCollaboration.h`, `ITrackerIssueMutations.h`, etc.) provide default implementations that return `TrackerErrorInvalidRequest("… not supported by this backend")`, so adding a backend never forces stubbing the full surface. The `Tracker/AGENTS.md` invariant "No backend leak into shared interfaces" (no `Jira*`/`Plane*`/`GitHub*` type in the six role headers) is the rule that *keeps* this abstraction clean over time — and it has an advisory `interface-doc` gate tying header symbol changes to the doc. The historical note "the old monolithic `ITrackerClient` was split into these — never reintroduce that name" is the abstraction's own regression guard.

**`ITrackerBackendFactory`** (`ITrackerBackendFactory.h`) is the injection seam that lets `main.cpp`, Unreal hosts, and tests substitute backends without touching `AppController.cpp`. Its docstring even encodes a hard-won correctness invariant (#979: must build from the caller's live `cfg`, never re-read config from disk, because the prefs save path races the debounced write) — design rationale living *in* the abstraction.

**Unified Command registry.** `CommandRegistry` (`Source/Core/src/Commands/`) is the single dispatch point for CLI, Command Palette, MCP, Lua, and Scenarios. The `Commands/AGENTS.md` "One registry, no bypass" invariant is the architectural keystone: every front-end reaches effects only via `Execute`, so fork-validation, logging, the structured error envelope, and the source-aware destructive-confirm gate (`RequiresExplicitConfirm(source, destructive, confirmed, dryRun)`) apply uniformly. The `ui-request-flag-off-thread` absolute-0 lint (Commands handlers may not write `g_ui.request*` outside a `RunOnUiThread*` closure) is a Pillar-3 data-race guard wired directly to this subsystem. This is a genuinely elegant fan-out abstraction: *register once, surface everywhere.*

**Dual render-target engine-agnosticism.** The core compiles against both GLFW/GL3 and DX12 by an enforced purity rule rather than `#ifdef` sprawl: `no-glfw-in-core-headers` is **absolute-0** over `Source/Core/include/**/*.{h,hpp}` (any GLFW/glad/OpenGL include in a core header breaks the DX12 build). This converts a fragile portability convention into a machine-checked invariant — the right tool for a constraint that is otherwise silently violated by a single stray include.

## 5. Executable Architecture Governance — the Novel Lens

This is the project's defining contribution, and it is sound. The thesis: **architectural rules are worthless as prose because prose does not block a merge.** Smatchet instead encodes them as delta-gated audits with a common, well-designed model.

**The gate model (consistent across all audits).** Each invariant is a Python audit (`include_cycle_audit.py`, `appcontroller_fan_in_audit.py`, `dup_audit.py`, `function_size_audit.py`, `agent_size_audit.py`) with identical ergonomics: a human-report mode, a `--diff <ref>` delta gate that compares HEAD against the merge-base, a `--selftest` that asserts the gate's own constants match the `AGENTS.md` contract-card, and a `--baseline-md` snapshot. The delta semantics are the key design: **existing violators are grandfathered, only NEW violations fail.** This is what makes adding gates to a large legacy tree tractable — you ratchet, you don't bulk-rewrite. The `SMATCHET_DEVIATION(rule=<id>; reason=…; owner=…; revisit=<date|slug|never>)` escape grammar (`cpp-rules.md:73-82`) is a zero-compile-cost comment that suppresses one rule on the next line, and an overdue `revisit=` date itself trips the `deviation-overdue` strict rule — **deviation debt has an expiry timer**, which is the single cleverest detail in the whole system. It means escape hatches cannot silently become permanent.

**Tiered enforcement** (`AGENTS.md` contract-card) is mature: strict zones (`Tracker/`, `Sync/`, `Persistence/`, `Config/`, `Commands/`, `Plugins/Mcp/`) fail on any violation; absolute-0 rules (`no-raw-new`, `no-detach`, `no-glfw-in-core-headers`, `app-controller-fan-in`) have no grandfathering; calibration rules (`duplication`, `unused-symbol`, `pr-numbered-temporal-comments`) start WARN-first and *graduate* to blocking only after a measured false-positive rate < 10% over ~20 PRs (the `duplication` gate did graduate, 2026-06-21, ADR-0015). This graduation discipline is genuinely sophisticated — it treats a lint rule like a product feature with a rollout, avoiding the "noisy gate everyone learns to ignore" failure mode.

**Per-subsystem `AGENTS.md`-as-ADR is sound and arguably superior to a central ADR folder for *scoped* invariants.** `Tracker/AGENTS.md`, `Commands/AGENTS.md`, etc. co-locate the binding rules with the code; `CONTEXT-MAP.md` is the registry, and `test-subsystem-docs.sh` enforces parity (a listed leaf missing on disk FAILs; an on-disk leaf absent from the registry FAILs; a rule string duplicated central↔leaf FAILs; code changed without a `README.md` touch WARNs). The duplication-FAIL is important: it prevents the classic doc-rot where a central summary and a local doc drift apart. The 22 cross-cutting ADRs in `docs/adr/` complement this for *project-wide* decisions (e.g. ADR-0011 single source root, ADR-0015 DRY gate, ADR-0013 solo-no-required-review). The division — leaf `AGENTS.md` for "rules that bind edits in this dir," central ADR for "decisions that bind the whole project" — is the right cut.

**Governance above the contract.** `AI_POLICY.md` separates *who is in control* (human owns quality + cost; agent autonomy is a revocable mode with two loop modes and an escalate-when-unvalidatable invariant) from *how to build* (`AGENTS.md`). The merge-gate poller (`merge-gates.sh`) is itself an architectural component — a four-condition machine check (CI + CodeRabbit + unresolved comments + Bugbot) that is the enforcement boundary for everything above. The `project.config.json` seam (`required_contexts`, `lint.zones`, `perf` budgets, `governance.loop_mode/auto_merge`) makes the whole portable layer parameterizable — `docs/STRUCTURE.md` defines a portable/project boundary with `test-portable-purity` preventing project literals from leaking into reusable dirs.

**Does it beat conventional architecture docs?** For *integrity over time*, decisively yes. A prose ADR saying "Core headers must not include GLFW" is violated by the next contributor's stray include and nobody notices for months; `no-glfw-in-core-headers` blocks the PR. A prose ADR saying "keep the include graph acyclic" decays; a Tarjan-SCC gate keeps it provably acyclic (2026 edges, 0 violations, *measured*). The governance layer's weakness is the inverse: it can only enforce what is mechanically checkable, and it carries a real authoring/maintenance cost (see §8).

## 6. What the Baselines/Governance Reveal About Hidden Debt

This is where the meta-layer earns its keep: the baselines are an **honest debt-ledger the code alone hides.**

**AppController fan-in — capped at 115, not fixed.** The fan-in audit reports 117 includers today (115 .cpp + 2 .h; `BASELINE_FAN_IN = 115` in `appcontroller_fan_in_audit.py:58`, enforced as a merge-base delta, ratchet-DOWN-only, hard-FAIL-absolute). The honest read: **115 TUs depend on one header is a god-object, and the cap institutionalizes it.** But two facts redeem this. First, the gate is *ratchet-down* — a new includer fails on sight (an exact, near-zero-false-positive signal, deliberately not WARN-first per the audit docstring), so the number can only shrink. Second, and more importantly, the *transitive include weight* has been aggressively cut even where the edge count is capped: `AppController.h:1-90` shows Lua/sol2 fully lifted to a src-only `Impl` (the ~100 includers no longer compile `<sol/sol.hpp>`), `nlohmann/json_fwd.hpp` instead of full json, AI controller forward-declared. So the fan-in *count* overstates the *coupling cost* — the governance work attacked the expensive part (compile-time transitive weight) while honestly leaving the count high and visible.

**The god-object is named, measured, and actively decomposed.** `docs/plans/shipped/appcontroller-god-object-decomposition.md` is a 200-line, phase-by-phase decomposition mirroring a proven 3-service ISP template (`I<Name>Deps` interface + `<Name>Service` owning its own state+mutex + adapter + header-only fakes + doctest). It is marked `shipped`, and the extractions are on disk: `EditMetaCacheService`, `FieldEditPipelineService`, `ConnectivityMonitorService`, `AttachmentAppUpdateService`, each behind `IEditMetaDeps`/`IFieldEditDeps`/`IConnectivityDeps`/`IAttachmentAppUpdateDeps`, joining the earlier `OfflineQueueService`/`TicketSyncService`/`LuaAutomationHost`. The decomposition's hard contract — "when state moves into a service, its mutex and every invariant move with it as a unit" — is exactly right for a refactor of a concurrent god-object. **The code alone would show a 1465-line header and look like unmanaged debt; the governance layer shows a header that is 7+ services lighter than it was and shrinking under a ratchet.**

**Duplication baseline (449 cross-file clones).** `dup-baseline.md` honestly catalogs 449 grandfathered copy-paste clones — most are legitimate per-backend `*Client.h` boilerplate and dual-target forward-decls (the standing exemptions named in `cpp-rules.md:59`). The gate is now blocking for *new* clones (graduated, ADR-0015), with the explicit and wise caveat that a DRY refactor coupling two independent subsystems is a code-review CRITICAL, not an improvement — i.e. the gate refuses to let DRY override modularity.

**Function-size and include-cycle baselines are at 0.** Both `function-size-baseline.md` and `include-cycle-baseline.md` report 0 grandfathered entries — these invariants have been driven to clean, not merely frozen. That is a strong signal: the "shrink-over-100-line-functions" and "core-include-dag" campaigns actually finished.

**The debt ledger and 255 postmortems.** `debt.md` entries are forensic — each cites `file:line`, traces data-flow (e.g. the DeepSeek config-sanitizer gap proven *not* exploitable via a use-site trace), assigns P-level and status. The 255-entry `postmortems.md` plus the "gate escapes owe a postmortem" rule (`AGENTS.md` Self-improvement) means every time a gate *failed to catch* something, a new gate is proposed. This is a self-tightening loop — the governance system improves its own coverage from its own failures.

## 7. Coupling/Cohesion Findings

**Cohesion is high within subsystems** and enforced by the leaf `AGENTS.md` invariants. `Tracker/` has a clear request flow (catalog → parser → payload; writes wire to offline queue + audit trail), and the "field-value flow is catalog → parser → payload" rule prevents bypass paths. `Commands/` has single-responsibility dispatch. The role-interface split keeps backend concerns from bleeding.

**Coupling is concentrated, named, and bounded.** The one high-coupling node is `AppController` (the documented "highest-coupling node in Source/Core — the merge-conflict + reasoning bottleneck"). The fan-in gate bounds it; the layer-DAG gate prevents it from acquiring upward dependencies; the decomposition plan reduces it. Elsewhere the graph is clean (2026 edges, 0 cycles). The `*Deps` interface pattern is the load-bearing decoupling mechanism — services depend on narrow capability bundles, not on the full AppController surface, which is what makes each service independently unit-testable behind a header-only fake.

**One residual coupling smell**: the `GridContextDepsAdapter` multiply-inherits the growing set of `I*Deps` interfaces (the plan itself flags "if the multi-inherit list grows unwieldy, a dedicated adapter" as an open question). As more services extract, this adapter becomes a new (smaller) fan-in point. It is the natural next thing to watch.

## 8. Architectural Debt & Risks (incl. meta-layer maintenance cost)

1. **AppController residual.** Even post-extraction the header is 1465 lines / 117 includers. The decomposition is real but incomplete in *count* reduction (the count rose 113→114→115→117 as features landed concurrently with extraction). Risk: the ratchet holds the line but the absolute coupling remains a reasoning/merge bottleneck. Mitigation already in flight; needs continued phases until the header is a thin facade.

2. **Meta-layer cognitive surface — the dominant non-code risk.** The governance system is *large*: a 28 KB root `AGENTS.md` (itself grandfathered at 156 lines over its own 150-line cap — `agent-size-baseline.md`), ~30 CI workflows, dozens of audit scripts and bats tests, 22 ADRs, a 255-entry postmortem ledger, a portable/project boundary, two VCS topologies (git + opt-in p4), and a self-improvement loop. For a **solo maintainer** this is a remarkable asset *while the maintainer holds the model in their head* and a serious onboarding/bus-factor liability otherwise. The governance layer has more conceptual surface area than many of the subsystems it governs. The `agent-size` gate and the AGENTS.md ≤150-line navigation-only constraint are the system's own attempt to bound this, and `debug-detective.md` (321 lines, grandfathered over the 250 cap) shows the constraint is already strained.

3. **Gates only enforce the mechanically-checkable.** Acyclicity, fan-in, function size, copy-paste duplication, include purity — all checkable. *Semantic* architecture quality (is this the right abstraction? does this service boundary make domain sense?) still rides on human/agent review and the prose invariants. The risk is false confidence: a green board proves the *encoded* invariants hold, not that the design is good. The project is aware of this (the duplication gate explicitly flags structural similarity as out of scope), but the gap is real.

4. **Perverse-incentive surfaces.** (a) *Grandfathering* can become a place debt hides — though the 0-entry include/function baselines show the team does pay down rather than perpetually grandfather. (b) *Deviation debt* is bounded by the `revisit=` expiry timer (good) but `revisit=never` and slug forms never expire (escape valve that could be abused; the `deviation-overdue` gate only catches calendar dates). (c) The *fan-in cap as a number* could incentivize satisfying the gate (forward-decl gymnastics to avoid a new include) over the real fix (extracting the dependency) — though here the forward-decl work genuinely reduced compile cost, so the incentive happened to align.

5. **C++14-hard cost.** The Unreal-compat C++14 floor bans `string_view`, `optional`, `variant`, structured bindings, `if constexpr`. This is a self-imposed ergonomic tax (the role interfaces use out-param-replacing structs like `TrackerIssueVotes` precisely because `optional`/`variant` are unavailable). Defensible given the Unreal embedding requirement, but it raises the cost of every abstraction and is permanent debt by constraint.

6. **126 KB CMakeLists as a single file.** The build system is one enormous, heavily-commented file (100 `.cpp` references, ~13 targets). The comments are excellent (every defensive guard cites the incident it prevents — e.g. the MSVC toolset-consistency guard's 5000-error-cascade rationale at `:79-117`), and `cmake-local-gate-ci-scope` is a lint guarding the build system itself. But a 126 KB monolith is a maintenance and review hazard; the debt ledger already tracks dead branches in it (the `SMATCHET_EMBEDDED_IN_UNREAL` dead-var-branch entry).

## 10. Prioritized Recommendations

1. **Finish the AppController decomposition to a thin facade and ratchet the fan-in baseline down with each phase.** The hard part (the service template, the mutex-moves-with-state contract) is proven; the remaining work is mechanical. Each shipped phase should *lower* `BASELINE_FAN_IN`, converting the cap from "institutionalized god-object" to "shrinking target." Watch the `GridContextDepsAdapter` multi-inherit list — split it before it becomes the next fan-in node.

2. **Treat the governance meta-layer's bus-factor as the top non-code risk.** It is superb but solo-held. Invest in a "governance onboarding" path (a single map doc: every gate, what it checks, where its source-of-truth constant lives) and consider whether any gate can be *retired* — the marginal gate's cognitive cost may now exceed its catch rate. The system's own `agent-size` constraint signals the maintainers feel this; lean into it.

3. **Decompose the 126 KB CMakeLists** into included `.cmake` modules per concern (third-party fetch, core target, render targets, plugins, lint guards), preserving the excellent incident-citing comments. This is the one piece of the architecture whose own monolithic shape contradicts the modularity the rest of the system enforces.

4. **Close the deviation-escape loopholes.** `revisit=never`/slug deviations never expire; add a periodic human-review surfacing of all non-dated deviations so the escape valve cannot silently accumulate. The calendar-expiry mechanism is excellent — extend its spirit to the open-ended forms.

5. **Add a semantic-review checkpoint where gates structurally cannot reach.** The gates prove encoded invariants; they do not prove the design is *right*. A lightweight per-ADR "is this still the correct decision?" revisit cadence (the leaf `AGENTS.md` invariants are the natural anchors) would cover the one gap the machine layer cannot.
