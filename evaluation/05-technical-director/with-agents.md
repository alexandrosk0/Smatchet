# Smatchet — Technical Director Evaluation (WITH agents.md)

*Lens: technical strategy, risk, delivery maturity, sustainability. Evaluated through the agentic-governance meta-layer that reframes the entire engineering picture.*

---

## 1. Executive Summary & Verdict

Smatchet is a ~218,000-LOC C++14 desktop application (issue/ticket tracker with a dual GL/DX12 render target, SQLite persistence, an HTTP layer, a Lua automation host, an MCP server, multi-vendor AI clients, Whisper dictation, an Unreal plugin bridge, and a mobile/Android lane) built and maintained almost entirely by **autonomous AI agents under a formal governance system**, driven by what `git shortlog` confirms is a **single human author** (Alexandros Konstantonis: 49 of 50 commits; the other is Dependabot). The substrate is wrapped in 27 CI workflows, ~273 gate scripts, 47 agent/governance markdown files, 22 ADRs, 151 shipped plan docs, and a 2,013-line append-only postmortem ledger with 51 real gate-escape RCAs — all produced inside an **8-day window** (first commit 2026-06-21, evaluated 2026-06-30).

The central question for technical direction is whether this governance meta-layer **credibly lets a near-solo human sustain this much code and breadth**, or whether the meta-layer is itself now the dominant tech-debt and key-person risk. My verdict, on the evidence: **this is genuine, unusually disciplined AI-native engineering — not a house of cards — but it is sustainable only as long as two external dependencies (the LLM agent fleet and its sole human operator/funder) both persist.** The governance is real, self-tightening, and demonstrably catches defects; the substrate decisions are conservative and defensible. But the system has bet its sustainability entirely on the continued availability and affordability of the agent harness, and the single most dangerous control — `governance.auto_merge: on` for a solo maintainer — concentrates merge authority in an LLM. The honest framing is "**impressive, working, but fragile at exactly two load-bearing points**," not "unsustainable" and not "bulletproof."

**Overall: 7.0 / 10** — strong substrate and exceptional process maturity for the team size, materially discounted by key-person/funding concentration and meta-layer carrying-cost.

## 2. Scope & Method

Evidence-based, strategic, read through the governance lens. I read: root `AGENTS.md` (the operating contract) and the five per-subsystem leaf `AGENTS.md` files (Sync, Commands, Persistence, Ui, Tracker); `AI_POLICY.md` (the human-authority charter); `project.config.json` (the single config home); the `agents/` tree (47 agent/skill markdown files across `core/`, `project/`, `_shared/`; ~173 shell/python scripts under `agents/scripts/`); `docs/agent-rules/**` (ship-loops, merge-gates, delegation, quality-pillars, process-rules, workflow-orchestration); `docs/self-improvement/postmortems.md` (51 gate-escape RCAs) and the `categories/*` backlog (43 entries); all 27 CI workflows including the agentic ones (`agentic-selftests`, `automated-pr-guard`, `cr-finding-gate`, `coverage-gate`, `dup-scan`, `plan-lock-gate`, the `lock-*` family); `.coderabbit.yaml`; and the substrate (`CMakeLists.txt` — 2,179 lines; FetchContent supply chain; subsystem source tree; 307 C++ test files + 56 bats suites).

I ran `git shortlog -sn --all`, LOC counts, and direct file reads. I did **not** delegate to sub-agents (per instruction). Findings below are framed as risks with likelihood/impact and cite the specific workflow, doc, script, or postmortem.

## 3. Engineering Substrate

**Language / stack bet.** C++14-**hard** is a deliberate, load-bearing constraint, not laziness: the root contract bans `string_view`, `optional`, `variant`, structured bindings, and `if constexpr`, and requires compilation on both MSVC and Clang. The stated rationale is **Unreal Engine compatibility** (the `Source/UnrealPlugins` bridge). This is a defensible strategic call — it keeps the core embeddable in an Unreal context — but it is a permanent tax: the team forgoes a decade of ergonomic, safety-improving language features (`std::optional` alone would eliminate a class of sentinel-value bugs). For an AI-agent-authored codebase this is a sound trade: the constraint is *machine-checkable* (a lint zone), so agents can't drift off it, and the narrower language surface reduces the space of constructs an agent must reason about.

**Dual render target.** `SmatchetStandalone` (GLFW/OpenGL) and `SmatchetCore_DX12` build the same core. This doubles the build/verify matrix and shows up repeatedly as a hard constraint in the lint rules (`no-glfw-in-core-headers` is an *absolute* zero-tolerance gate because a GLFW/OpenGL include in a core header breaks the DX12 target). It is the single biggest source of "behaviour-preserving but untestable" diffs in the postmortem record (the recurring `tests-out-of-band` header-lift cases, #1308/#1317). Strategically this is feature-rich but is a long-term maintenance multiplier.

**Dependencies / supply chain.** Ten FetchContent dependencies (nlohmann/json, cpr, SQLiteCpp, cpp-httplib, md4c, ghc::filesystem, glfw, sol2/Lua, whisper.cpp, ImGui). Hygiene here is **good**: every dependency I inspected is **pinned to a full commit SHA** (e.g. json `9cca280a…` = v3.11.3, cpr `f88fd773…` = 1.9.2, sol2 `902ceaf8…` = v2.20.6), not a floating tag or branch — this defeats the most common FetchContent supply-chain risk (a moved tag silently changing the build). Dependabot is wired in with an auto-merge + self-heal guard (`automated-pr-guard.yml` re-runs failed Dependabot CI once, then labels for human attention). There is a `THIRD_PARTY_LICENSES.md` and a fallback URL mechanism for the Lua tarball (lua.org fallback when codeload 504s). The residual risk is the usual one: a transitive CVE in `cpr`'s bundled curl or in whisper.cpp, surfaced only by Dependabot cadence. Acceptable for a prerelease solo project.

**Build system.** A 2,179-line `CMakeLists.txt` plus a 29KB `CMakePresets.json` is a large, feature-flagged build (`SMATCHET_WITH_AI`, `_LUA_AUTOMATION`, `_MCP`, `_MCP_UNREAL`, `_WHISPER`, plus an "AI/Whisper/MCP off" light configuration that is a *required* CI context). The feature-flag matrix is itself a tested invariant — the `unused-symbol-under-config-guard` lint exists specifically because a feature-OFF build once broke (#863). This is mature, but the CMake file's size is a smell; it is the kind of artifact that only an agent fleet with a config-skew gate can safely keep coherent.

**CI maturity.** 27 workflows is the headline substrate strength. The matrix covers: dual-toolchain `/WX` builds, ASAN (MSVC) + UBSan (Clang) + nightly TSan (Linux subset), OpenCppCoverage with a numeric floor (65%, ramping to 70%) **and** a structural test-delta gate, perf (PR-fast + full, with a 6.94 ms frame budget = 144 Hz and a 10 ms/100 Hz p99 floor as a *hard* quality pillar), libFuzzer smoke, CodeQL, mobile emulator + Android security gate, fresh-clone-configure nightly, and shell-lint. Ten contexts are branch-protection-required. This is a CI suite most funded teams of 5–10 do not reach. It is, candidly, only buildable *because* agents wrote and maintain it.

## 4. The AI-Native Delivery Model as Strategic Bet

This is the heart of the evaluation. The project is not "a C++ app that happens to use AI tools" — it is **an AI-native delivery system whose product happens to be a C++ app**. The governance stack is the actual engineering achievement.

**The control model.** `AI_POLICY.md` is a human-authority charter sitting *above* the `AGENTS.md` operating contract (the structure is borrowed from Ghostty, adapted). It establishes: humans own quality and cost; agent autonomy is a *granted, revocable mode*; everything is auditable; and two loop modes — `on` (human-on-the-loop, action-biased) and `in` (human-in-the-loop, plan-gated) — bound autonomy. A standing **"escalate-when-unvalidatable"** invariant fires in *both* modes: before acting, the agent must be able to autonomously validate (a gate/test/spec confirms correctness, scope is authorised, cost is bounded); if it can't, it escalates rather than assuming. This is a genuinely thoughtful safety architecture — it names the exact failure mode of autonomous agents (confident hallucinated "validation") and routes around it.

**Velocity vs control.** The default is the **autonomous ship-loop**: `diagnose → fix → build → code-review → commit → push → open PR → gate-check → squash-merge → cleanup → backlog`, run end-to-end *in one turn* with clarifications batched once at the start. Combined with `governance.auto_merge: on` (set 2026-06-23, explicitly justified: "solo maintainer, low review availability"), the human is removed from the per-PR merge decision entirely. Velocity is clearly very high — 50 commits and 151 shipped plans in 8 days. The control compensation is the **merge-gates poller** (`merge-gates.sh`): before any squash-merge it checks CI (every required check + a meant-to-block allow-list), CodeRabbit, unresolved human comments, and Cursor Bugbot, in one GraphQL call. The design philosophy is explicit and sound: **"gate, don't trust."**

**Does the governance credibly sustain the breadth?** On the evidence, *yes, for now*. The breadth (tracker + P4 + Lua + MCP + multi-vendor AI + Whisper + Unreal + mobile) exists **because of** agents, not despite them — no solo human writes a fuzz harness, a TSan subset, an Android security gate, a 144 Hz perf budget enforcer, *and* ships features in 8 days. The governance is what makes that breadth not collapse into chaos: strict lint zones (`Tracker/`, `Sync/`, `Persistence/`, `Config/`, `Commands/`, `Mcp/`), delta-gated lint (only *new* violations vs `origin/develop` block; existing ones grandfathered), per-subsystem leaf docs, an include-cycle/layer-DAG gate, an AppController fan-in ratchet (cap 115, ratchet-down-only), and a DRY duplication gate graduated from warn to blocking.

**The self-tightening loop actually works.** This is the most important finding. The postmortem ledger (`postmortems.md`, 51 entries) is not theater — it contains real, blameless, technically precise RCAs of defects that *escaped* gates, each ending in a *mandatory new gate*. Examples that demonstrate the loop catching real defects:
- **#1265-class** (merge-watcher daemon crash, 2026-06-15): an unhandled `subprocess.TimeoutExpired` (which is `subprocess.SubprocessError`, *not* `RuntimeError`) escaped a caller's `except RuntimeError`, crashed the shared daemon, and stranded every registered PR. RCA produced five concrete gates including a per-PR and per-cycle exception backstop, and — notably — a *cascade* sibling instance was caught by an **adversarial Workflow verification pass on the diff before merge**, i.e. the "gate, don't trust" pattern catching a second bug during the fix for the first.
- The **recurring "native merge bypasses the custom poller"** class (#1406/#1414/#1415, #1428, #1438, #1566): five+ separate escapes where a bare `gh pr merge --auto` / direct REST `PUT` / human native-merge merged past a *meant-to-block-but-not-GitHub-required* check (`Intent section`, `Perf PR-fast`) because GitHub-native merge paths only honor branch-protection-required contexts and never consult `merge-gates.sh`. The remedy evolved from advisory ("prefer the poller") → enforced (`safe-merge.sh` as the *only* sanctioned merge entry-point) → promotion of the check to a required context with a precondition. This is a textbook self-tightening loop: same class recurred, the system escalated the rigor of the gate each time.

That recurring class is *also* the most damning evidence about the model's fragility (see §6): the governance keeps discovering that its own custom enforcement layer can be silently bypassed by the platform's native paths, and `auto_merge: on` arms exactly those paths.

**Cost / reproducibility.** The project takes cost seriously *in principle*: `AI_POLICY.md` makes token/compute a "human-governed budget," there is an `agents/_shared/token-tracking/` toolchain (per-agent token log, statusline, skill-load log), and the contract recommends a "caveman" output-token compressor (~75% cut) by default. But the charter itself admits "an automated cost-ceiling *gate* is a separate follow-up" — i.e. the binding control is still a *principle*, not an enforced gate. The true recurring cost of running this fleet (every PR triggers CodeRabbit + Bugbot reviews, multi-turn agent ship-loops, a continuously-running merge-watcher daemon polling 250+ cycles in the wedge incidents) is real and unmeasured here.

## 5. The Meta-Layer as Both Asset and Liability

**As asset.** The meta-layer *is* the product's quality moat. ~173 scripts under `agents/scripts/`, 56 bats suites, 47 agent docs, 22 ADRs, and the postmortem ledger together encode an enormous amount of hard-won operational knowledge — every one of the 51 postmortems is a permanent regression guard. The `agentic-selftests.yml` workflow is a particularly telling artifact: it exists because the "gate, don't trust" test suite (the bats layer testing the locks/guards/merge-gate-logic itself) "historically ran ONLY at a local pre-push gate that nothing actually invoked — so a regression in the merge-gate logic could merge green (the suite gated nowhere)." In other words, **the project gates its own gates**, and discovered (and fixed) the fact that its meta-layer was untested. That is a mark of real maturity.

The portability discipline is also genuine: `project.config.json` is a single home for project-specific values, the portable dirs (`agents/core/`, `agents/_shared/`, `docs/agent-rules/`, `docs/harness/`) are forbidden from hardcoding project facts (guarded by `test-portable-purity`), and `docs/harness/` carries adapters for Claude Code, Codex, and Cursor. The meta-layer was designed to be *liftable* into another project — which means it is an asset with reuse value beyond Smatchet itself.

**As liability.** The carrying cost is now substantial and is the project's dominant *internal* tech-debt:
- **Sheer size.** 47 agent docs + ~173 scripts + 27 workflows + 2,013-line postmortem ledger + 151 shipped plans + a 28KB root `AGENTS.md`. The contract has had to impose *size gates on itself* (`agent-too-long`: 250-line agent cap, 150-line `AGENTS.md` cap, with grandfathered whales) — the meta-layer grew large enough to need its own anti-bloat lint. A human onboarding to maintain this without the agents would face a multi-week comprehension task.
- **Complexity of the merge path.** The merge logic now spans `merge-gates.sh`, `safe-merge.sh`, `safe-admin-merge.sh`, `merge-watcher.py`, a snapshot ledger (`merge-snapshots.jsonl`), an out-of-band-label system (5 labels), a block-allow-list regex, a freshness self-guard, and a documented set of "sharp edges." A solo human *cannot hold this in their head* — it is only operable via the agents that wrote it. The merge-watcher daemon stale-logic escape (#1428) is the canonical liability: a long-running daemon silently ran two-day-stale gate logic and *self-reported clean* because the audit row is written by the stale poller itself.
- **Who maintains the maintainer?** This is the key-person risk in its purest form. The governance system is sophisticated enough that maintaining *it* now requires the same agent fleet that maintains the product. There is no evidence of a second human who could take over either the product or the governance. The charter explicitly scopes itself to "this solo-maintained, prerelease project" and waves off external-contributor rules "while solo."

## 8. Strategic Recommendations

1. **Treat the bus-factor as the #1 strategic risk, not a footnote.** The entire system rests on one human who is operator, funder, and the only person who understands the governance. Produce a *human-readable, agent-independent* architecture-and-operations digest (a "what is this, how does it build, how does it ship, what breaks if the agents stop" document) maintained as a first-class artifact, so the project survives a fleet outage as something a new human can pick up. This is the single highest-leverage action.

2. **Narrow `auto_merge: on`.** The strongest evidence in the postmortem ledger is that native merge paths repeatedly bypass the custom poller (R3). Combined with auto-merge arming exactly those paths, the highest-risk subsystems (`Persistence`, `Sync`, `Config` — data integrity and concurrency) should require a human merge tap. Scope auto-merge to docs/tooling/UI diffs and keep core data-path changes human-gated even at a velocity cost. The charter already supports per-PR revocation; make core-path human-merge the *default*, not the exception.

3. **Close the cost-control gap with an enforced gate, not a principle.** `AI_POLICY.md` names cost as human-governed but admits the automated ceiling is a TODO. Given a solo funder, an unbounded agent run is a real financial risk. Ship the per-session/per-PR token-budget gate that escalates before overspend — the token-tracking substrate already exists to power it.

4. **Promote the remaining meant-to-block checks to branch-protection-required contexts** (with the documented path-filter preconditions), eliminating the entire poller-bypass class (R3) at the platform layer rather than continuing to patch the merge-actor side. The ledger shows the loop already moving this way (#1566); finish it.

5. **Budget down the meta-layer's carrying cost.** The governance is an asset but its size is now self-acknowledged debt (the `agent-too-long` self-gate). Periodically consolidate the postmortem-driven gate proliferation — some of the ~273 scripts are likely subsumable — and resist adding a bespoke gate for every single escape where a class-level guard already exists (the ledger's own "none — override legitimate" entries show good judgment here; institutionalize it).

6. **De-risk the C++14-hard bet's downside.** The Unreal-compatibility rationale is sound, but verify it is *still load-bearing* (is the Unreal bridge actually shipping, or aspirational breadth?). If Unreal embedding is deferred, the C++14 tax buys nothing and should be relaxed to a more modern baseline that recovers `std::optional`-class safety — directly improving the "never crash" pillar.

**Bottom line.** This is not a house of cards — the gates are real, the postmortems are real, the loop demonstrably tightens, and the substrate is conservatively sound. It is, instead, a genuinely impressive AI-native engineering system with two unhedged single points of failure (the fleet and its sole human) and one over-permissive control (`auto_merge`). Address the bus-factor and narrow auto-merge, and this is a sustainable model. Leave them as-is, and it is a high-velocity system one funding-or-staffing event away from becoming an un-maintainable inheritance.
