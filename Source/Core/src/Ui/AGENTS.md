# Ui subsystem — agent rules

Scoped rules for `Source/Core/src/Ui/` (all ImGui render code: panels, the ImGui host and theme, docking, the ticket grid UI and the annotate views). Global rules stay in the root [`AGENTS.md`](../../../../AGENTS.md). Draw-function decomposition pattern: [`docs/guides/imgui-draw-pattern.md`](../../../../docs/guides/imgui-draw-pattern.md).

`Ui/` is a **light** lint zone (`agent-layer/docs/agent-rules/cpp-rules.md` § Tiered enforcement) — existing inline exemptions apply — but it hosts the richest UX-pillar checklist, because every freeze the user feels originates on this thread.

Checkable rules sit under **Invariants**; file maps and procedures under **Before you edit**. Rules for files outside this directory that these panels depend on live in a header comment of those files; the bullets below point to them.

## Invariants

### UI-thread non-blocking (Pillar 2)

Flag any of these when reachable from `SmatchetUI::Draw` or any ImGui render path. These are **correctness** issues, not "performance" — they cause visible hitches and a CRITICAL review finding:

- `cpr::Get` / `cpr::Post` / `cpr::Put` / `cpr::Delete` directly in render code — must go through `TrackerHttpClient` posted to a worker thread.
- `SQLite::Database` calls inline in a render frame — the work must run on a worker thread; post only the result back via `MainThreadDispatcher::PostToMainThread`, and chunk large writes (`SmatchetChatPersistWorker` is the reference pattern).
- `p4 ...` invocations (any `system()`, `_popen`, child-process spawn) — must run on a `std::thread` worker (see the `AnnotateAnalysisUi.cpp` pattern).
- Synchronous file I/O (image decode + upload, font load, attachment download) on the UI thread — use `std::async(std::launch::async, …)` and poll per frame.
- `std::future::get()` without a prior `wait_for(0s)` ready-check — blocks the frame.
- **Single-slot async loads: get the latch ORDER right, or the pane wedges for the session.** Route them through `LaunchIntoSlot` / `TakeFromSlot` in [`AsyncLoadGatePure.h`](../../include/Ui/AsyncLoadGatePure.h) rather than hand-rolling. Publish the in-flight latch only AFTER the launcher returns a future (`std::async` throws `std::system_error` when threads are exhausted, leaving a latch over an invalid slot), and clear it BEFORE `get()` (a worker exception is rethrown by `get()`, so clearing after it never runs). Either mistake makes every later poll early-out forever on a load that can never land. This has bitten three times in this directory — the plan-doc viewer's read launch (#2056), its poll (#2057), and its index pair (#2108) — and `LuaConsolePlugin::KickScriptLoad`/`PollScriptLoad` documents the same hazard. It is worst where the retry button is itself gated on the latch, which removes the pane's only manual recovery.
- **Report a failed keyed read against the key it was FOR, not the live key.** `get()` destroys the payload on a throw, so the poll has no `result.key` to fall back on — record the key at launch. Reaching for the current selection instead names the wrong document, and parking the load gate on it convinces the gate that document is already loaded, so it never loads (#2108). Reuse `ResultIsCurrent` to decide whether the failure still describes what the user is looking at.
- `std::thread::join()` anywhere outside shutdown / destructor paths.
- `std::this_thread::sleep_for` on the UI thread — never legal.
- Long lambdas posted to `MainThreadDispatcher` — `Drain()` reads its 4 ms budget clock only between tasks, so one oversized task is still a spike; chunk + repost instead.
- Holding a `std::mutex` across an HTTP / SQLite / p4 / file-I/O call from any thread (the UI thread waiting on that mutex = a spike).
- **A timeout bounds a blocking call; it does not make it safe.** The field-icon fetch `HttpGetBinary` (`SmatchetFieldIconRender.cpp`, `cpr::Get` with a 3 s timeout) must stay inside its `LaunchBackgroundTask` lambda, marked `/* PILLAR2_WORKER_ONLY */` with its `// est-latency:`. On the UI thread a 3 s timeout is a 3 s stall; the same holds for every `cpr::Timeout` / `cpr::ConnectTimeout` reachable from render code.
- **Lua over budget.** The sandbox hook (`lua_sethook` with `LUA_MASKCOUNT`) caps instructions, not wall time, and a call into C++ is one instruction, so a binding that does expensive C++ work (a catalog rebuild, an image fetch) stalls the frame from inside a single Lua call. Per-cell renderers take the cached-replay path (`register_field_display_cached`; cost figures in `docs/guides/lua.md` § Rules).
- **First-touch work.** Work paid once per key on the UI thread — rasterising a glyph (ImGui 1.92 bakes glyphs on first use), decoding an image, building a lazy lookup — spikes once and then looks fine, so a steady-state capture never shows it. Warm it at startup or move it to a worker instead of paying it on first draw.
- **Background-apply bursts stay row-capped.** Per frame, `TicketSyncService::TickStreamingApply` merges at most `kFetchedRowsPerFrame` (20) fetched and `kUnchangedRowsPerFrame` (500) cache-served rows into the roster (the sync worker already persisted them), and `AppController::TickAllContexts` shares a 4 ms deadline across panes. Their clocks are read only between slices and between panes, so the budget is a row count, not a timer: a change that raises a cap or adds per-row work re-measures the frame.
- New owners of `std::thread` / `std::async` futures missing the join contract in their destructor — `~AppController` (with `BeginShutdown()` + join) is the reference pattern; a missing join → `std::terminate`.

### Offline-first reads (Pillar 6)

- **Never render a loading-only state while cached data exists.** A network-backed view (combo, modal, panel, cell) draws its cached value and a `DataFreshnessCue` (`Source/Core/include/DataFreshnessCue.h`); "Loading…" alone is only for `DataFreshness::LoadingNoCache`. Offline, a tracker request spends up to ~90 s in its retry window, so a loading-only branch looks frozen and hides data the user already has (the PR #2234 status combo and the comments modal both did this).
- **Keyed lookups go through `KeyedLookupCache` + `RunKeyedFetch`** (`Source/Core/include/KeyedLookupCache.h`): no fetch while `IsOfflineState`, a failure backs off and is never remembered as loaded, and the in-flight flag clears on every path including a throw.
- **A row-scoped option list never borrows another scope's list.** The components editor and cells use the row's own project list, live or saved, and fall back to the catalog's list only when the catalog was fetched for that same project (`ComponentOptionsPickPure.h`); otherwise the cue says the list is not available yet.
- **"Nothing found" only describes a live answer.** An empty-list or "no such user" message ("No projects found.", "Past Employee") is shown only when the tracker actually answered; a failed or skipped lookup shows the saved copy (project list: `ProjectListLookup`; users: the saved roster) with its cue, or says it is unknown or unavailable offline, and offers a Retry. Take the typed call (`ListProjectsTyped`, `SearchUsersByQueryTyped`) so an unreachable tracker (`Transport`) is never read as "none".
- **A lookup the user reopens keeps its last answer.** The watchers / votes windows and User Info show what they loaded earlier this session, with the cue, while a refresh runs, while the tracker is offline (no request is sent) and after a failed load, and they offer Load / Retry instead of an error dead end.
- **Attachments open from disk once downloaded.** Previews and opens go through `ResolveAttachment` (`Source/Core/include/AttachmentDiskCache.h`): a cached copy answers with no request, a miss while offline says it is not downloaded yet, and every entry stays under `attachment_cache/` (path-confined, 256 MB LRU).
- **A tracker error banner never discards the user's edits.** Only the Read-only preference may drop not-yet-sent grid edits; a banner-driven read-only state holds them until the tracker is usable.
- **Toasts say what happened.** "Queued" only after a real enqueue, "Posting…" while a request is in flight; never "Queued" for a direct post.
- **A tracker write is bound to the pane the user acted in.** Latch a `PendingActionTarget` where the user acts (`LatchPendingActionTarget`, or `LatchPendingActionTargetForPane` for a grid pane) and carry it to the send, the queue row and the local update (`SubmitFieldEditOrQueue`, `SubmitOrQueueComment`, `PendingFieldEdit::Target`). Never re-read the focused pane on the worker: focus can move between the click and the send, and the write would reach another tracker (#2260).

### Steady-state perf (Pillar 1)

- Steady-state UI work ≤ 6.94 ms (144 Hz); p99 ≤ 10.0 ms. Profile with `SMATCHET_UI_PERF_SCOPE` markers, not by eye.
- **Per-cell grid code allocates nothing per row.** The cell paths (`SmatchetFieldRender`, `SmatchetFieldIconRender`, the row loop in `SmatchetActiveProjectGridTable.cpp` and `SmatchetActiveProjectGridCells.cpp`) hoist string building and map lookups out of the per-cell call: the grid draws every visible cell every frame, so one allocation there is multiplied by rows × columns. A change to a per-cell path is re-measured with `SMATCHET_UI_PERF_SCOPE` per [`docs/guides/perf-workflow.md`](../../../../docs/guides/perf-workflow.md) before it is called regression-free.

### Docking

- **Never dock to a slot constant without the liveness guard.** The `SmatchetDockNodeIds.h` constants name slots the *default* layout cuts, and any of them can be gone at runtime: the user dragged the last tab out and the node collapsed, the `.ini` predates the slot, or (`kSecondarySideBar`) no layout ever cut it. `SetNextWindowDockID` to a dead id does not fail: ImGui mints an orphan root node, so the window looks docked but owns no slot until the user drags a splitter. Use `DockNextWindowOnFirstUse(slot)` for a first-use dock; any other write (an `ImGuiCond_Always` re-dock) calls `EnsureDockSlotAlive(slot)` first and skips the write when it returns 0 — leaving the window floating, which is visibly wrong and therefore fixable.
- **A new slot constant needs a node in the default layout.** `tests/bats/dock_node_ids.bats` (`scripts/dev/test-dock-node-ids-bats.sh`) fails when a `constexpr ImGuiID k*` in the header has no `DockNode ID=` in the embedded default ini (`ConfigManager.cpp`). `kSecondarySideBar` (0x10) is its one allow-listed orphan, pending the cut-a-node-or-delete-the-feature decision in debt entry `2026-08-07-dock-node-id-slot-liveness-followups`.
- **`ImHashStr` drops everything up to and including `###`.** On a `###` it resets the hash to the seed and steps past the marker, so `ImHashStr("Foo###Bar") == ImHashStr("Bar")`. A window id is `ImHashStr(name)`, so a source title and its localized rendering get the same id — and keep their dock slot and saved settings — as long as both carry the same `###` suffix. Keep that suffix on every translated window title.
- **Layout migration runs at boot, before the ini loads.** Runtime `LoadIniSettingsFromDisk` does not re-parent windows that already exist at their old dock ids, so a dock-layout reset placed in a per-frame `Draw` silently does nothing. `SmatchetImGuiHost::Initialize` (in `initImGuiContextAndBackend`) runs the `ConfigManager::kCurrentLayoutSchemaVersion` check before it assigns `io.IniFilename`; `SmatchetUI::drawInitConfigOnce` keeps only a post-first-frame fallback reset. The other boot paths and the bump procedure are listed beside the constant in [`Config/ConfigManager.h`](../../include/Config/ConfigManager.h).

### Host and theme

- **Style is two layers.** `ImGui::StyleColorsDark()` seeds ImGui's substrate and `SmatchetTheme::ApplyStyle` paints the Smatchet look. `ApplyStyle` resets `style = ImGuiStyle{}` and rebuilds from the palette on every call (the first one on frame 1, from `drawApplyAppearanceSettings`), so a persistent write to `ImGui::GetStyle()` fields at a call site is silently undone: change the palette in `SmatchetTheme.cpp`. Scoped `PushStyleColor` / `PushStyleVar` and reading style metrics are fine.
- **A new palette token gets a WCAG-AA contrast CHECK where the token sits on a known bg**, in a `tests/Core/SmatchetTheme*.test.cpp` doctest (`SmatchetThemeAccentContrast.test.cpp` is the reference). A `float[4]` token with no CHECK can regress contrast unseen.

### Grid

- **A grid cell edit commits only through the edit pipeline.** Grid UI code (cell editors, panes, the new-issue row) hands a `PendingFieldEdit` to `EnqueueGridFieldEdits` (once per visible pane); `PumpGridFieldEdits` (once per frame, one edit in flight) sends it to `CommitOrQueueFieldEdit` on a worker and posts the result back. A new editable field type produces a `PendingFieldEdit`; it never gets its own commit branch or a direct tracker-client call, which would skip the offline queue and the audit trail.
- **Grid status reaches the user through `SmatchetGridNotifications` and cell feedback.** Tracker-connectivity and grid banners become toasts through `MaybeToastTrackerConnectivityBanner` / `MaybeToastGridBannerFromSession` (deduplicated against the last toasted kind and message); a cell's own commit state is its `cellFeedbackByKey` entry, set by the edit pipeline. No ad-hoc status text (`ImGui::Text("Saved")`) for either.
- **Column widths come from the view, not from cell contents.** `SmatchetActiveProjectGridTable.cpp` sets every column `WidthFixed` from the view (`EffectiveColumnWidth`, else `DefaultColumnWidthPx`, both in `ViewColumnsPure.h`) once per frame, reads the widths back after layout to persist a user resize, and virtualises rows with `ImGuiListClipper`. A width measured from data fights both; an auto-fit goes through `GridPane::pendingAutoFitColumn`.
- **The views dashboard owns view CRUD; the grid renders the active view.** Creating, renaming, deleting and editing view definitions belongs to `SmatchetViewsDashboardUi*`; grid code changes the live view only for in-grid gestures (sort, header-drag reorder, width capture, header-menu column removal) and autosaves them.

### Annotate views and syntax highlight

- **An approximate annotate row stays visibly approximate.** `P4LineAnnotate::Approximate` marks a row whose changelist and user came from the `p4 changes -m 1` fallback, not from annotating that line. `AnnotateAnalysisUi*` shows that in every view and export (row tooltip, the CSV / JSON `approximate` column) and never presents such a row as a confirmed blame.
- **`LineSnippet` is export context, not display.** It carries the source line into the Jira comment, CSV / JSON and AI exports; the annotate views draw code from `P4AnnotatedLine::Code`.
- **Callstack frames are filtered and remapped only with the parser's helpers.** The analysis worker (`AnnotateAnalysisUi_Worker.cpp`) drops frames with `FrameMatchesIgnoreKeywords` and rewrites paths with `ApplyPathRemaps` (`CallstackParser.h`); draw code never re-filters frames or rewrites paths itself.
- **`CppSyntaxHighlight` draws; `CppSyntaxLex` classifies.** Token rules live in the pure `CppSyntaxLex.{h,cpp}` and are shared by the annotate views, `CodeColorView`, the plan-doc viewer, the markdown preview, field render and the ticket field editor, so a lexing change shows in all of them. Colours come only from `SmatchetTheme::GetSyntaxColors()`. Both work on text already in memory: no file, network or `p4` access.

### Frame state and focus

- Gate per-window mutations on live `IsWindowFocused`/this-frame focus, never a previous-frame flag — same-frame mouse-down focus races stale flags (PR #962 review: 3 of 4 HIGHs were this one pattern).
- Second-order of the rule above: when you OPEN a gate to this-frame focus, re-verify every context object the gated mutation writes through was resolved for THIS pane/window — a newly-admitted frame may still carry a fallback-resolved object (e.g. the other backend's active view), and the mutation lands in the wrong target (PR #962 delta-review HIGH).
- Any `ViewState` store mutation that resizes `store.Views` (`Create`, `DeleteActive`) goes through a top-of-`Draw` deferral latch (`applyPendingViewCreate`/`applyPendingViewDelete`) — NEVER mid-frame from a click handler: the reallocation/erase dangles every `ViewDefinition*` resolved earlier in the frame (PR #962 user-repro crash). In-place mutations (`UpdateActive`, `Activate`) are pointer-stable and exempt.

## Before you edit

- Diagnose a hitch or freeze with `docs/guides/perf-workflow.md` § Spikes (characterise, scan, scope plan, long capture, spike-vs-steady classification, off-thread fix patterns, re-measure); sustained slowness follows § The loop of the same guide.
- **UI-thread model.** One UI thread runs `SmatchetUI::Draw` per frame. Early in every Draw, before the desktop or mobile window code, `MainThreadDispatcher::Drain()` (perf row `MainThreadDispatcher::Drain`) runs posted tasks FIFO until its 4 ms `DrainBudget()` is spent and requeues the rest for the next frame. Workers post back with `PostToMainThread` (droppable: bounded at 4096, oldest dropped on overflow) or `PostCompletionToMainThread` (a latch-releasing completion with its own 4096 bound, never evicted by droppable traffic); `perf.memory` reports `dispatcherQueueLen`, `dispatcherLastDrainTasks` and `dispatcherLastDrainDeferred`. Long-running workers own a `std::thread` with a shutdown flag and a destructor or `Stop()` join — `automationWorker_` (Lua), the `TicketSyncService` streaming `WorkerThread`, the `BackendAuditTrail` writer, the `Logger` file sink, `AnnotateAnalysisUi`'s `WorkerState::Thread` (p4), `ConfigSaveWorker`, `SmatchetChatPersistWorker`, `AiAssistantController::worker_`; mirror that shape rather than adding a threading primitive. One-shot work runs in `std::async(std::launch::async, …)` polled per frame with `wait_for(0s)`; `DrainUiDrawSessionFuturesBeforeAppTeardown` (`SmatchetUI.h`) waits for the `UiDrawSession` futures that capture `app`, and `~AppController` calls `mainThreadDispatcher.BeginShutdown()` and joins its workers before members die.
- **Re-check sites.** These calls block and sit one edit away from the UI thread; re-check which thread runs them whenever their caller changes: the attachment-upload `cpr::Post` in `Tracker/JiraIssueMutation.cpp` (`AttachFilesToIssue`, reached from `IssueCreatePipeline`), and the SQLite writes `TicketSyncService::ApplyIssueFetchPack` makes on the UI thread between sync sessions.
- A `Draw*` / `Render*` function approaching 200 lines uses the section-helper pattern (`DrawCtx` + `DrawHeader`/`DrawBody`/`DrawFooter`/`DrawModals`/`HandleHotkeys`) per [`docs/guides/imgui-draw-pattern.md`](../../../../docs/guides/imgui-draw-pattern.md), including its § Verification per-file `--scan-file` step (the `--diff` gate grandfathers a function that was already over cap). Existing monoliths are ride-along only.
- Any new sync-stall path > 100 ms needs a visible cue (spinner/disabled state) and bucket-E coverage.
- A per-frame override of a window's geometry / dock id / visibility IS that window's live state, and ImGui's settings writer snapshots `Pos`/`Size`/`DockId` **off the live window** (omitting the `DockId=` line while it is 0). The debounced auto-save and the unconditional save in `DestroyContext` therefore persist the override as if the user had put the window there. Say in the header what the app writes at exit, or make the override not be the live state — no test bucket can observe it today (`docs/self-improvement/categories/test/2026-08-05-no-bucket-e-shutdown-relaunch-primitive.md`).
- **Grid file map.** A new column or cell editor: the field type in the tracker catalog (`Source/Core/src/Tracker/AGENTS.md`, catalog → parser → payload), display in `SmatchetFieldRender` / `SmatchetFieldIconRender`, grid routing in `TrackerGridFieldDisplay`, commit through the edit pipeline above (`SmatchetGridFieldEditPipeline.cpp`). Sort order: `TicketGridSortPure.{h,cpp}` (`CompareFieldValuesForSort`; doctest `tests/Core/TicketGridSortPure.test.cpp`). Header-drag reorder, width capture and header-menu column removal: `SmatchetActiveProjectGridTable.cpp` with `ViewColumnsPure.h` / `GridColumnOrderPure.h`. Toolbar above the grid (sort-by popup, view picker, search, chips): `SmatchetGridHeaderUi`.
- **Host file map.** Lifecycle: `SmatchetImGuiHost.{h,cpp}` (`Initialize`, `Shutdown`, `BeginFrame`, `DrawUI`, `RenderDrawData`, input plumbing, `SetSuppressSoftwareCursor`) and the C ABI in `SmatchetImGuiHostC.h`. Theme: `SmatchetTheme.{h,cpp}` (`ApplyStyle`, `GetSyntaxColors`, the `SmatchetTheme*Colors` palettes), `SmatchetThemeIds.h`, `SmatchetThemeDensity.h`, `SmatchetThemedTextEditorPalette`. Dock slots: `SmatchetDockNodeIds.h`. Default font: `SmatchetApplyImGuiDefaultFontWithExtendedGlyphs` (`SmatchetImGuiFonts.h`). The boot files that create the ImGui context sit outside this directory (see Docking above).
- **User-facing text goes through `SmatchetLocalization::T(key, englishFallback)`** (`SmatchetLocalization.h`; `Label` / `WindowTitle` / `Format` for ImGui labels, window titles and format strings) — never `Loc(...)`, `Translate(...)` or a new wrapper. Keep the call-site fallback and the table's English column in step: `agent-layer/docs/agent-rules/cpp-rules.md` § Localization.
- **A theme or dock-init change** fires the visual-validation pause unless bucket-C/E coverage exists (root `AGENTS.md` § Autonomous ship-loop default, exception 5). A host or theme header change builds both targets (`agent-layer/docs/agent-rules/cpp-rules.md` § Dual-target).
- **Widening a shared contract needs an approved plan.** A new dockspace topology, a reshaped host API (`SmatchetImGuiHost.h` / `SmatchetImGuiHostC.h`) or a new `ViewDefinition` storage / serialization shape needs an approved § Interface contracts entry in the active plan (`docs/plans/active/<slug>.md`, written with the `author-plan-doc` skill or the `architect` agent). Without one, stop and ask the user.
- **The annotate data layer** (Perforce spawn, describe cache, `PathRemaps`, ignore keywords, the zero-credential tests) is documented in the header comments of `P4Annotate.h` and `CallstackParser.h` (`Source/Core/include/`).
